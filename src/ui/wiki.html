このアプリについて

Google ドキュメント / スプレッドシート / スライドに、Git と同じ考え方の 版管理を与えるものです。文書を直接書き換えるのではなく、 ブランチを作って変更し、レビューを経て main に反映する という流れで進めます。

基本の流れ

  1. Issue を作る — 「Issue」タブで、何を直すかを書きます
  2. ブランチを作る — Issue の「このIssueでブランチを作る」を押します。 issue-12-在宅勤務規定 のような名前が自動で付きます
  3. 編集する — 左上でそのブランチに切り替えてファイルを開き、 「編集」タブで書き換えます。Google ドキュメントを直接開いて編集しても構いません
  4. コミットする — 「本文」タブの「コミット」を押します。 ここで初めて履歴に残ります
  5. PR を作る — 「ブランチ」タブの「PRを作る」を押します。 説明に closes #12 と書くと、マージ時に Issue が自動で閉じます
  6. レビューして マージする — 「プルリクエスト」タブで差分を見て、 承認してからマージします。main の文書が書き換わります

つまずきやすい点

main が編集できません

意図的にそうしています。main を直接書き換えると誰がいつ何を変えたのかが 残らないため、変更は必ず PR を通します。Google ドキュメント側で main を 直接編集してしまった場合は、「直接編集を退避」ボタンで記録してください。 退避しないとマージができません。

「コンフリクトあり」と出ました

同じ行を main 側とブランチ側の両方で書き換えたときに出ます。赤枠の中で 「main側を採用 / ブランチ側を採用 / 両方を残す」を選んでからマージしてください。 別々の行を直しただけなら自動で統合されます。

「書き戻せません」と出てマージできません

文書の中に、このアプリが復元できない要素があります。ほとんどの場合は 実体を取得できない画像です。そのままマージすると画像が 永久に失われるため、手前で止めています。Google ドキュメント側で画像を 貼り直してからやり直してください。

色やフォントが履歴に出ません

色・フォント・文字サイズは版管理の対象外です。このアプリは 「文書の意味内容」を管理するもので、見た目の変更は差分になりません。 全角スペースによる字下げも同様に失われます。

スライドで PR が作れません

スライドは閲覧・履歴・差分までの対応です。図形の位置や大きさを 復元できないため、マージには対応していません。反映は Google スライド上で 直接行ってください。
