# 人と工数

[手引きの目次](README.md)

## 見える範囲

人に関わる数 (工数の内訳・使われ方の人ごとの数) は、**本人と部下のぶんだけ**見える (`memberVisibleTo`)。
全員が全員の数字を見られると、見張られているように感じて、正直な実績が入らなくなるためである。入らない数字は
集計しても意味がない。

| 数 | 誰でも | 本人 | 上長 |
|---|---|---|---|
| チーム全体の合計 | 見られる | | |
| 人ごとの内訳 | | 自分のぶん | 下の人 (下の下まで) のぶん |

例外はホームの「週の上位」だけで、守りは [ホームとポイント](home-and-game.md#ポイントとレベル-既定オフ) にある。

## 上下関係を登録する

台帳の `members` シートに行を足す。`email` にその人、`manager` に上長を書く。

| email | manager |
|---|---|
| buka@example.com | naka@example.com |
| naka@example.com | boss@example.com |

この例では `naka` は `buka` を、`boss` は `naka` と `buka` を見られる (下の下まで届く)。下から上、および横は見られない。
輪になる関係は登録できない。

- 画面から変えられるのは**管理者だけ** (誰でも書き換えられると、自分を上長にして他人の数字を覗けてしまう)
- GAS エディタからも書ける

```js
memberSet('buka@example.com', 'naka@example.com');  // 登録・付け替え
memberSet('buka@example.com', '');                  // 関係を外す
memberSet('buka@example.com', 'naka@example.com', '部下 一郎');  // 名前も一緒に
```

## 画面に出す名前

担当者や書いた人は、既定ではメールアドレスの `@` より手前で出る。名前を決めておくと目で追いやすい。

- 自分の名前は、上の帯の自分の顔 →「表示する名前を決める」で決める。ほかの人の画面にもこの名前で出る
- 他人の名前は、管理者だけが変えられる
- 名前は `members` シートの `name` 列に入る。上下関係とは別に扱うので、どちらか一方だけでもよい

```js
memberSetName('aoki@example.com', '青木 太郎');
```

## 担当が複数いる仕事の工数

ひとつのやることに担当を何人でも割り当てられる。工数は集計のときに**頭数で割って**数える。

- 4人日を2人で持てば、それぞれ 2人日 として数えられる
- チーム全体の合計は 4人日 のまま

それぞれに全部を足すと、人ごとの合計を足しても全体の合計に戻らず、どちらの数字を信じてよいか分からなくなる。
割り当てた本人にその場で分かるよう、2人以上にした時点で入力欄の下に断り書きが出る。集計の「人ごと」の表の脇と、
画面の「使い方」にも同じことを書いてある (この規則を直すときは3か所とも直す)。

ポイントとレベルの点も、担当が複数なら頭数で割る。

## 工数の欄

| 欄 | 単位 |
|---|---|
| 予定工数 | 人日 (0.5 きざみ)。台帳の列名は `plannedHours` だが中身は人日 |
| 実績工数 | 人日。列名は `actualHours` |
| 見積もり | 規模を表す数 (`estimate`) |

親子にしたやることは、親に子の工数を足し上げて見せる。期間ごとの集計は [やること](tasks.md#集計) にある。
