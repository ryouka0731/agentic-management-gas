# 目標 (OKR・MBO・KPI)

[手引きの目次](README.md)

期ごとに目標を立て、上長に承認してもらい、済ませたやることと入れた数から進み具合を自動で出す。
**既定はオフ。** 管理者が設定の「チームの設定」で `goals.enabled` (目標 (OKR・MBO・KPI) を使う) をオンにすると、
左に「目標」が出る。区切り (`goals.period`、既定は半期) と年度の始まる月 (`goals.fyStart`、既定は4月) もそこで決める
([設定](settings.md))。

**自動の見立ては目安でしかない。** 評価を決めるのは上長で、番頭は決めない。人事の評価にどう使うかはチームが決める。
ポイントとレベル (ゲーム) の数は使わない。

## 期

期は年度で切る。4月始まりなら、上期 = 4月〜9月、下期 = 10月〜翌3月、第1四半期 = 4月〜6月 …。
key は `2026H2` (2026年度 下期) / `2026Q3` (2026年度 第3四半期) の形で、目標ごとに台帳に残る。区切りを途中で変えても、
立てた目標の期は変わらない (前の期の目標も、期の選び方から辿れる)。**年度の始まる月も目標ごとに、立てたときの値を残す**
(`goals.fyStart` を変えても、立てた目標の期の日付は動かない)。上長の期の選び方には、見られる下の人の目標の期も出る。

## 種類

| 種類 | 何を決めるか | 自動の見立て |
|---|---|---|
| OKR | 目指す姿と、届いたかを測る主な結果 (2〜5つが目安) | 0.0〜1.0 の点 (小数1桁)。**0.7 前後なら狙いどおり**、1.0 は目標が低めだったかもしれない |
| MBO | 期のはじめに上長と決める目標。項目ごとの重みを**合わせて100**にする (承認を頼むときに確かめる) | 達成率 (%) と段 |
| KPI | 追いかける数。目標の値に対する今の値 | 達成率 (%) と段 |

段は `GOAL_GRADES()` (src/core/GoalScore.js) が唯一の定義: **S** 120%以上 / **A** 100%以上 / **B** 80%以上 / **C** 60%以上 / **D** それ未満。

## 進み具合の数え方

項目ごとの進み具合 p を出し、目標全体は **重み付きの平均** Σ (p × 重みの割合) にする。

重みの割合 = その項目の重み ÷ 重みの合計。**重みが1つも書いていなければ等しく分ける** (OKR の主な結果はふつう同じ重さ)。
1つでも書いてあれば、書いたものだけで分ける (空は0)。

| 測り方 | p の式 |
|---|---|
| つないだやることの完了 | 済んだやることの重さ ÷ つないだやることの重さの合計。重さは予定の工数 (人日) で、無ければ1件を1。**期の中 (始まり以後・終わりより前) に完了したものだけ**を済んだと数える。捨てたものは数えない。つないだものが無ければ 0。1 を超えない |
| タグの付いたやることの数 | 件数 ÷ 目標の値。件数は、**担当に本人が入っていて、期の中に完了し、決めたタグが付いた**やること (担当が何人いても1件。タグの大文字小文字は見ない。捨てたものは数えない) |
| 数を入れる | 今の値 ÷ 目標の値 (負は 0) |
| できた・まだ | できた = 1、まだ = 0 |

上限: OKR の項目は 1.0 まで。MBO・KPI の項目は **1.5 (150%) まで** (1つの項目の超え方で全体が決まらないように)。

期の中での進み方: 経った割合 − 進み具合 (1 で止める) の差が 0.1 以下なら「順調です」、0.25 以下なら「少し遅れ気味です」、
それより大きければ「遅れています」と添える (`GOAL_PACE()`)。届いていない数は赤くせず「あと3件」のように出す。

## 流れ

1. 「目標を立てる」— 種類・名前・項目を決めて保存する (下書き)
2. 「上長に承認を頼む」— 項目が1つ以上要る。MBO は重みの合計が100
3. 上長が「承認する」か「差し戻す」(差し戻すときは、直してほしいことを書く)。差し戻されたら直して頼み直す
4. 進める — やることをつなぐ (目標の項目の「やることをつなぐ」か、やることの詳細の「目標につなぐ」)・今の値を入れる・
   できたに印を付ける。**これらは承認し直しが要らない**
5. 承認のあとに**目標そのもの (名前・種類・項目) を直すと、もう一度承認を待つ** (上長に知らせが届く。今の値とつないだやることは残る)
6. 期の終わりに本人が振り返りを書き、上長が評価 (S〜D) とひとことを付ける。評価済みになると、もう誰も直せない
7. 「期末のまとめ」で、進み具合・項目・振り返り・評価を1つの字にして写せる (評価の書類や面談のメモに貼る)

下書きと差し戻された目標は消せる (つないだやることそのものは消えない)。**一度承認された目標は、差し戻されたあとでも消せない**
(承認した記録として残す)。承認を待つあいだは、本人が「承認の頼みを取り下げる」で下書きに戻せる (上長に知らせが届く)。
承認済みの目標を何も変えずに保存しても、承認し直しにはならない。

### つなげるやること

- つなげるのは**目標を立てた本人が担当のやること**。担当がいなければ、**本人が作ったもの** (変更の履歴の「作った人」で見る)。
  ほかの人のやることや、この期より前に完了したやることはつなげない (やることの詳細の「目標につなぐ」も、本人のやることにだけ出る)
- 数えるのは期の中に完了したものだけ (台帳を手で直してつないでも、期より前に済んだものは数えない)
- **承認済みの目標から、完了したやることを外すと承認し直しになる** (進み具合が下がり、承認した中身と変わるため。上長に知らせが届く)。
  まだ完了していないやることを外すのは自由

### 評価を付ける時

評価 (S〜D) を付けられるのは、承認された目標のうち**期が終わったか、本人が振り返りを書いたもの**だけ (画面とサーバで同じ決まり)。

## 誰が何を見られるか

| 人 | 見る | 直す・値を入れる・振り返り | 承認・差し戻し・評価 |
|---|---|---|---|
| 本人 | ○ | ○ | × |
| 直属の上長 ([人と工数](people-and-effort.md) の上下関係) | ○ | × | ○ |
| その上の人 (上長の上長 …) | ○ | × | × |
| 上長が登録されていない人の目標: このアプリの持ち主 | ○ | × | ○ |
| ほかの人・管理者 (上の連なりにいない) | × | × | × |

**管理者だというだけでは見えない。** 人に関わる数は本人と上長の連なりの外に出さない。持ち主に上長がいなければ、持ち主は
自分の目標の承認を頼めない (上下関係を登録する)。目標は探す欄・ホームの最近の動き・使われ方・ポイントのどれにも出ない。
ただし台帳 (`goals` / `goal_items` / `goal_links`) は入れ物の中にあり、Drive で台帳を開ける人は直に読める。

## 知らせ

承認を頼んだ → 承認する人へ。承認した・差し戻した・評価を付けた → 本人へ。画面の中の知らせ (鈴) と通知メールの両方に出る。
メールは自分の設定の「通知メール: 目標の承認・差し戻し・評価」(`notify.goal`) で止められる。知らせが届かなくても、承認や評価は済んでいる。
