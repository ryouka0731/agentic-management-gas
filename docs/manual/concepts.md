## 直接なおさず、コピーで直して確認を経る

規程や手順書は、誰かが直接書き換えると「いつ・誰が・なぜ」が残らない。番頭では次の順で進める。

```
正式版 ──コピー──▶ 改訂版 ──直す・記録──▶ 確認依頼 ──承認──▶ 正式版に反映
```

1. **正式版** (main) — いま効力を持つ版。全員が見る。画面からは直接なおせない
2. **改訂版** (ブランチ) — 正式版の Docs / Sheets をコピーした作業用の版。ここで直しても正式版に影響しない
3. **変更の記録** (コミット) — ある時点の中身を丸ごと残したもの。記録した人と時刻と一言が付く
4. **確認依頼** (プルリクエスト) — 「この改訂版を正式版に反映してよいか」を尋ねる。承認が要る
5. **反映** (マージ) — 承認された中身を正式版の文書に書き戻す。文書の fileId は変わらないので、共有リンクは壊れない

長い改訂は、途中の改訂版を土台にして分けて進められる (確認依頼は改訂版どうしでも出せる)。

## 中で何が起きているか

### すべてを正規化した HTML にする

Docs / Sheets / Slides を、すべて同じ形の **正規化 HTML** に変換する。この HTML が Git の blob にあたる。

```
Google Docs   ─┐
Google Sheets ─┼─▶ 正規化 HTML (1ブロック = 1行) ─▶ 行ごとの差分 / 3つを見比べる反映
Google Slides ─┘
```

1ブロックを1行にし、属性の順・空白・装飾の入れ子の順 (太字 → 斜体 → 下線 → 取り消し線 → リンク) を固定して
いる。そのため **同じ内容からは常にバイト単位で同じ HTML が出る**。Git と同じ行ごとの差分も、3つを見比べる
反映 (3-way merge) も、そのまま使える。

この形 (`src/core/Normalize.js` の `serializeBlocks`) を変えると、過去の全記録と食い違って履歴が壊れる。
変えるときの決まりは [CLAUDE.md](../../CLAUDE.md) の「出力を変えてはいけない」にある。

### 2つの層

| 層 | 実体 | 使い道 |
|---|---|---|
| いまの層 | Drive 上の文書そのもの | 「本文」で読む。常に最新が見える |
| 記録の層 | `.git/objects/<sha>.html` | 履歴・差分・確認依頼・反映 |

いまの層は文書の最終更新時刻をキャッシュの鍵に含めている。Docs で編集すれば、次に表示したときから新しい
中身が出る。同期の仕掛けは要らない。

### Drive の中の置き場

`setupRepo()` が、スクリプトと同じフォルダに次を作る。

```
agentic-management/          入れ物 (名前は改名前のまま)
├── main/                    正式版の文書を入れる場所
├── branches/                改訂版の作業コピー
└── .git/
    ├── objects/             変更の記録の中身 (正規化 HTML) と、コードの差分の本文
    ├── queue/               手元からの命令と結果 (初めて使うときに作られる)
    ├── queue-done/          処理済みの命令
    ├── kit/                 配る道具の zip
    ├── shots/               要望・不具合に添えた画像
    └── agentic-management repo-db   台帳のスプレッドシート
```

台帳には、文書・記録・改訂版・確認依頼・やりとり・やること・進捗ボード・タグ・下書き・人・知らせ・報告・
使われ方・頼みごと・スプリントなどの表がある。列の並びは `src/core/Db.gs` の `DB_SCHEMA()` が唯一の定義で、
列は必ず末尾に足す。人が手で書き換えてもよい表だが、`'` で始まる字は番頭がそう書いたもの (数式や日付に
化けないための印) なので消さない。

## 何を版管理するか

| 種別 | 読む・履歴・差分 | 改訂版・確認依頼 | 反映 (書き戻し) |
|---|---|---|---|
| Docs | できる | できる | できる |
| Sheets | できる | できる | できる (変わったセルだけを書く。数式は `data-formula` に退避して保つ) |
| Slides | できる | — | **できない** (確認依頼を出す時点で断る) |

- **色・フォント・文字サイズは記録しない。** 意味の変わらない見た目の調整は差分に出ない (意図的な割り切り)
- 全角スペースによる字下げは正規化で失われる
- Sheets は表示値を中身とする。セルの中の改行は1行に潰す (1ブロック = 1行を保つため)
- Slides は図形の座標を HTML から戻せないので、読むことだけにしている
- 実体を取れない画像を含む文書は、書き戻すと画像が永久に失われるので、反映そのものを断る

## コードは git が持つ

確認依頼には、コードの差分を「証跡」として添えられる ([文書と確認依頼](documents-and-reviews.md#コードの差分を添える))。
ただし番頭はコードの版管理をしない。承認されても、コードは書き換わらない。取り込むのは手元の git である。
番頭が持つのは「人が画面で読んで、進めてよいと決めた」記録だけ。

## 版の管理のほかに出てくる言葉

版の管理とは別に、画面には次の言葉が出る。どれも人の評価には使わない。

| 言葉 | 意味 | 手引き |
|---|---|---|
| 推し | 済ませたときにほめてくれるキャラクター。最初からいるキャラか、自分で作ったキャラ | [推し](oshi.md) |
| 実績 | 開いた日 (通算)・済ませた数・はじめて使った機能で取れるバッジ。本人にだけ見え、一度取ったら消えない | [実績](achievements.md) |
| なつき度 | 推しがどれだけなついたか。Lv で数え、1 + 取った実績の数。よそよそしい (Lv1) → なれてきた (Lv5) → なついた (Lv15) → べったり (Lv25) → 家族 (Lv35)。上がると推しが自分のことを少しずつ教えてくれる。下がらない (機嫌はその日の気分で、別のもの) | [推し](oshi.md#なつき度) |
| クリア | 取れる実績を全部取ったこと。推しのプロフィールが全部分かる | [推し](oshi.md#プロフィールとクリア) |
| 機嫌 | やることが滞ったときの推しの表情とせりふ (既定オフ)。何も取り上げない | [推し](oshi.md#機嫌) |
| ポイントとレベル | 片づけた重さと確認の返事で付く、ホームの数 (既定オフ)。推しのなつき度とは別のもの | [ホームとポイント](home-and-game.md#ポイントとレベル-既定オフ) |
| 作業部屋 | 環境音を流し、推しが机で作業している部屋を眺める場所 (既定オフ) | [集中のしかた](focus.md#作業部屋) |
| 作業雑談部屋 | チームの Meet / Slack の部屋に、いま誰がいるかを見る場所 (既定オフ) | [作業雑談部屋](cowork.md) |
| 使われ方 | どこがよく押されたかの、その日の回数だけの記録 | [使われ方](usage.md) |
