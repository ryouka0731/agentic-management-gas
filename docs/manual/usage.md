# 使われ方

[手引きの目次](README.md)

左の「使われ方」は、どこがよく押され、どの画面がよく開かれているかを見る画面。使われていない所を見つけて直すための
もので、**人を見張るためのものではない**。実装は `src/core/Usage.gs` (数える・まとめる)、`src/api/People.gs` の
`apiUsageRecord` / `apiUsageSummary` / `apiUsageRows` (誰のぶんを返すか)、画面は `src/ui/js-me.html` の `loadUsage`。

## 守っていること

- 残すのは **「日・種類・場所・回数・押した人」の5つだけ**。押した順番・時刻・文書や書き込みの中身は残さない
- 人ごとの数は **本人と部下のぶんだけ** 見える。管理者だというだけでは、ほかの人の数は見えない
- 本人はいつでも自分のぶんを止められる。チーム全体は管理者が止められる
- 記録は台帳の `usage` シートにだけ置き、外へは送らない

## 何を数えるか

台帳の `usage` シートに残るのは「日・種類・場所・回数・押した人」の5つ。

| 列 | 中身 |
|---|---|
| 日 | 東京の暦日 (`yyyy-MM-dd`)。時刻は残さない |
| 種類 | `view` (画面や節を開いた) と `action` (押した) の2つ |
| 場所 | 名前 (英数と `:` `_` `-`、60字まで) の付いた場所 |
| 回数 | その日に、その人がその場所を何回押した・開いたか |
| 押した人 | サーバ側で決める (`Session.getActiveUser()`)。画面から受け取ると名乗りを詐称できるため |

数える場所は次のとおり。

| 場所 | 場所の名前 | 例 |
|---|---|---|
| 左の行き先 (画面) | `tab-<画面>` | `tab-issues` (やること)・`tab-usage` (使われ方) |
| 名前の付いたボタン | 部品の id か、決めた名前 | `issue-create-btn` (やることを作る)・`report-copy` (日報にコピー)・`focus-start` |
| 一覧の行やカード | 種類でまとめた名前 | `row-open` (やること・報告の行)・`board-card`・`gantt-bar`・`doc-open`・`commit-item`・`rel-chip` |
| 使い方の節 | `guide-<節の id>` | `guide-usage` (使われ方の見方)・`guide-room` (作業部屋) |
| 時間切れで止まった操作 | `error:timeout` | 下の「時間切れの数」 |

- 名前を付けていない場所は数えない (作りかけの画面から知らない名前が流れ込まないように)
- 一覧の行やカードは1つずつではなく、**種類でまとめて**数える (どの文書・どのやることを開いたかは残らない)
- 押すたびには送らず、画面側でまとめてから送る (使われ方の画面を開いたときにも、それまでのぶんを送る)。一度に受け取る場所の数には上限 (60) がある
- **手元の道具 (`agent.mjs`) からの命令は数えない。** 数えるのは画面の上で押したもの・開いたものだけ
  (手元から命令を置いたかは、実績の「手元の道具を使った」のために別に覚えている。[実績](achievements.md))

### 使い方の節を開いた数

使い方の節は、**読みに来たときだけ** `guide-<id>` として1回数える。読まれていない節を見つけて直すため。

- 数えるとき: 目次で節を押した・絞り込みで1件だけになった (打ち足しても同じ節なら数え直さない)・
  画面の見出しの横の **「?」** を押した・探す (Ctrl+K) で節を選んだ
- 数えないとき: 送って通り過ぎた・見出しを押した (見出しは押す物ではない)
- 「?」がある画面: ホーム・文書・やること (工程表を見ているときは「文書と工程表の見え方」へ)・確認依頼・使われ方・設定・目標
- 節の id は変えない。変えると過去の数が別の場所に分かれ、「?」が何も開かなくなる ([docs/dev/ui.md](../dev/ui.md))

### 時間切れの数

画面で時間がかかりすぎて止まった操作 (Apps Script の実行時間の上限などで打ち切られたもの) は、サーバでは数えられない
(打ち切られるため)。そこで画面が `error:timeout` として数える。使われ方の画面では「時間切れで止まった操作」と出る。

- **番頭が重くなっていないかを見るための数** で、押した場所の人気とは関係ない
- 管理者の「成果の数」の **時間切れ** はここから足す ([管理](admin.md#成果の数))。使われ方を止めた人のぶんは入らない
- 増えてきたら、台帳が大きくなっていないか、同じ時刻に重い操作が重なっていないかを疑う

## 数えないもの

- **自分の設定「自分の使われ方を記録する」(`usage.self`) を外した人** が押したもの。外すと画面から送ること自体をやめ、
  サーバでも断る
- **チームの設定「使われ方を記録する」(`usage.enabled`) が止まっているあいだ** は、誰のぶんも数えない
- 止める前に数えたぶんは消えない。残す日数を過ぎたときに、ほかの行と一緒に落ちる
- 設定が読めないときは数え続ける (止めたつもりの無い人の記録を黙って落とさない)

## 誰のぶんが見えるか

| 何を | 誰が見られるか |
|---|---|
| 場所ごとの合計 (順位・曜日・日ごと) | 誰でも。個人が写らないので、全員ぶんを出す |
| 人ごとの数 (よく使っている人の並び・「対象」の切り替え) | 本人と、本人が上長として登録されている人 (その下の人も)。[人と工数](people-and-effort.md#見える範囲) |
| CSV の人の列 | 上と同じ範囲の人の行だけ |

- **管理者でも、上下関係の外の人の数は見えない。** 誰が何をどれだけ使ったかは個人の働き方そのものなので、上下関係の外には見せない
- 見られない人を「対象」に名指ししても断る (`その人の使われ方は見られません`)

## 画面の見方

上で **期間** (直近7日 / 30日 / 90日。最初は30日) と **対象** (みんな / 自分と部下の1人) を選ぶ。選び直すたびに頼み直し、
古い返事は捨てる (選び直したあとに前の期間のまとめが出ないように)。

| 上から | 中身 |
|---|---|
| 4枚のカード | 数えた回数・数えた場所・対象・期間。数えた回数には、同じ長さの直前の期間との増減 (±% と矢印) を添える。前の期間に記録が無ければそう出る |
| よく使っている人 | 人ごとの回数。見られる人のぶんだけ。押すとその人を対象にする |
| よく押されている操作 | `action` の順位表。前の期間との増減を小さく添える |
| よく開かれている画面 | `view` の順位表 (使い方の節もここに「使い方: 〈見出し〉」と出る) |
| この期間に開かれなかった画面 | 左の行き先のうち、一度も開かれなかったもの。期間で進めるがオフなら、その画面は除く |
| 曜日ごと | 月曜から日曜までの7本の棒。時刻は残していないので、時間帯は分からない |
| 日ごと | 日ごとの回数 |

まだ記録が無いときは「まだ記録がありません」と出る。

### CSV で保存

今見ている期間と対象の、**日・場所・人ごと** の数を CSV で落とす。

- **見られない人の行は入れない** ので、画面の合計とは合わないことがある。名前を空にして数だけ残すと、
  見られない人が1人のときその人の記録がそのまま読めてしまうため
- 保存できないとき (Apps Script の枠の中で断られたとき) は、字をそのまま写せる形で出す

## 止める・残す日数

| 何を | 誰が | 設定 | 既定 |
|---|---|---|---|
| 自分のぶんを数えない | 本人 | 自分の設定「自分の使われ方を記録する」(`usage.self`) | オン (数える) |
| チーム全体の記録を止める | 管理者 | チームの設定「使われ方を記録する」(`usage.enabled`) | オン (数える) |
| 残す日数 | 管理者 | チームの設定「使われ方を残す日数」(`usage.keepDays`) | 180日 (90〜365日) |

- 画面で直近90日まで見るので、90日より短くはできない。90日を見るときの「前の期間との比較」は、残っている日のぶんだけになる
- 古い行は、記録のついでに落とす (日が読めない行は落とさない)
- 行の数は「日 × 場所 × 人」で頭打ちになる (1日に何回押しても、同じ場所・同じ人なら1行)

## 使われ方を使うもの

- **実績** — 「Markdown で保存した」「日報をコピーした」「探す (Ctrl+K) を使った」「推しを選んだ」は使われ方の場所で確かめる。
  使われ方を記録しないときは取れない ([実績](achievements.md))。使われ方の記録が古くなって落ちても、取った実績は残る
- **改善のヒント** — 使い方の問い合わせが続いているかは、使われ方ではなく報告の数で見る ([ホームとポイント](home-and-game.md#改善のヒント))
- **成果の数** — 時間切れの数 (上) ([管理](admin.md#成果の数))
