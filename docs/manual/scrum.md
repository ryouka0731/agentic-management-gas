# 期間で進める (スクラム)

[手引きの目次](README.md)

AI のチームメンバー (手元の Claude) と一緒に、期間を区切って進めるための機能。`ai-scrum-gas` から取り入れた
(計画: [エージェンティックスクラム](../superpowers/plans/2026-10-07-agentic-scrum.md))。使わないチームのほうが
多いと見て、**既定ではオフ**にしてある。オフのあいだは何も変わらない。

## 2通りの言葉

スクラムの言葉はエンジニア以外には通じにくいので、画面では**一般の言葉**を既定にしている。自分の設定
**「言葉の表し方」** (`terms.style`) で「スクラムの言葉 (エンジニア向け)」を選んだ人にだけ、スクラムの言葉で出す。

| 一般の言葉 (既定) | スクラムの言葉 |
|---|---|
| 期間で進める | エージェンティックスクラム |
| 作業期間 | スプリント |
| この期間の目標 | スプリントゴール |
| 大きさ | ポイント |
| 期間ごとに終えた量 | ベロシティ |
| 残りの量の推移 | バーンダウン |
| 困りごと | 障害物 |
| 目指すところ | プロダクトゴール |
| 終わったと言える条件 | 完了の定義 |
| できたと言える条件 | 受け入れ条件 |

- 対応の唯一の定義は `src/core/Terms.js` の `TERMS()`。画面の字は `term(key)` を通す
- **変わるのは表示だけ。** 台帳の列名・API 名・データ・命令の名前は変えない
- **サーバの断り文は一般の言葉に固定する。** 人ごとに切り替えると、キューやトリガーから出る文の言葉がばらつくため
- ホームの**ゲームのポイント**はスクラムの見積もりとは別物なので、「ポイント」のまま
- 使い方の節の見出しは「期間で進める (使う人だけ)」に固定する
- 手元の道具のスキル (`kit/SCRUM.md` など) はエンジニア向けなので、スクラムの言葉のまま

設計: [使い方・使われ方・設定 の 4](../superpowers/specs/2026-10-20-guide-usage-settings-design.md)。
以下、この頁では一般の言葉を先に、スクラムの言葉を括弧で書く。

## オンにする

管理者が左の「設定」の「チームの設定」で **期間で進める (エージェンティックスクラム)** をオンにする。
目指すところ (プロダクトゴール) と、終わったと言える条件 (完了の定義) もそこで書く。

- オンかどうかはスクリプトプロパティ `SCRUM_ENABLED` が `'true'` かで決まる
- オフのあいだ、関係する画面・欄・命令は出ないか断る。**状態を見る命令 (`scrumState`) だけはオフでも通す**
  (オンにするよう案内するため)。手元から切り替える命令は無い
- 確かめるには GAS エディタで `debugVerifyScrum()` ([実機で確かめる](verification.md))

## オンにすると変わるもの

- 左に **作業期間 (スプリント)** と **困りごと (障害物)** が出る
- やることに **作業期間・大きさ (ポイント)・できたと言える条件 (受け入れ条件)** の欄が付く。できたと言える条件は1行に1つ書く
- 探す (Ctrl+K) で困りごとも探せる
- 日報の「困っていること」に、自分が出した未解決の困りごとが入る

## 作業期間 (スプリント)

- 名前・この期間の目標・始まりと終わりの日を決めて作り、やることをそこへ積む
- 画面の上に「次にすること」が1つだけ出る。順にこなせば、計画 → 進める → 見せる → ふりかえる の1巡りが回る
- **残りの量の推移 (バーンダウン)** と **期間ごとに終えた量 (ベロシティ)** は、やることの大きさと完了日から自動で数える。
  数を手で書く場所は無い (手で書いた数は必ずずれる)。ロードマップも同じ数から描く
- 終わった作業期間は、**終わりの日の時点の中身**で数える。終わらなかったやることを次へ移しても、前の期間の計画から
  消えずに「持ち越し」として数えられる。終わった期間へ後から入れた記録は、始まりから入っていたものとして読む
- 進め方は進捗ボードで列を動かし、終わったら完了にする

## 困りごと (障害物)

進みを妨げているもの。気づいた人が書き出し、取り除けたら解決策を書いて「解決した」にする。やりとりを書ける。
開き直せる。

## 変更の履歴

やることと困りごとの欄がいつ誰にどう変わったか (作業期間を移したことを含む) を台帳の `change_log` に残す。
やることの詳細の「変更の履歴」で見られる。やることの履歴はオフでも見られ、困りごとと作業期間の履歴はオンのときだけ。
履歴を残せなくても、本処理は巻き戻さない。

## 手元から

```sh
node agent.mjs scrum                       # オンか (オフなら進めない)
node agent.mjs sprints                     # 作業期間の一覧
node agent.mjs sprint-add sprint001 "申請の流れ" 2026-10-01 2026-10-14
node agent.mjs sprint-edit sprint001 '{"goal":"…"}'
node agent.mjs scrum-view [sprint001]      # 残りの量の推移・期間ごとに終えた量
node agent.mjs impediments                 # 困りごとの一覧
node agent.mjs impediment "題名" "中身"
node agent.mjs impediment-resolve 3 "代理が承認"
node agent.mjs changes issue:12            # 欄の変更の履歴
```

落とした道具の zip には、スクラムを進めるためのスキルとチームの役割 (`.claude/skills/` `.claude/agents/`)、
ai-scrum-gas の CSV との読み替え (`SCRUM.md`)、文章の成果物のひな形 (`scrum-templates/`) が入っている。
スプリントの記録・振り返り・依頼書・仕様といった文章は、手元の `scrum/` に書く (台帳には入れない)。
ひな形は `scrum/` に無いものだけ写す (zip を展開し直してもチームが書き足したものを上書きしないよう、
ひな形は `scrum/` という名前では配らない)。

オンにしても、確認依頼の承認と設定の変更は人が画面で行う。
