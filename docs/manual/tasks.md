# やること

[手引きの目次](README.md)

やること (Issue) は、誰かがやるべき作業。文書に紐づけてもよいし、紐づけなくてもよい。左の「やること」に、
5つの見え方がある。

| 見え方 | 内容 |
|---|---|
| 一覧 | まとめ方 (文書ごと / 担当者ごと / 状態ごと / ラベルごと / まとめない) を選んで並べる |
| ボード | 進捗ボード。列を掴んで動かす |
| 工程表 | 開始日から期限までを棒で並べる |
| 集計 | 予定と実績の工数を期間ごとに足し上げる |
| 捨てたもの | 捨てたやることの置き場。30日のあいだ戻せる |

上の欄で、題名・担当・ラベル・文書名で絞れる (`/` でその欄へ移る)。「自分の担当だけ」で自分のぶんに絞る。

並び順は、一覧が優先度の高いものから (同じなら新しいものから)、ボードが人の並べた順。

## やることの中身

| 欄 | 内容 |
|---|---|
| 題名・補足 | 補足は Markdown で書ける (`## 見出し` `- 箇条書き` `- [ ] 手を付けたかの印` `**強い字**` `[名前](リンク)`) |
| 担当 | 何人でも割り当てられる (アドレスのカンマ区切り)。工数の数え方は [人と工数](people-and-effort.md#担当が複数いる仕事の工数) |
| 優先度 | 高 / ふつう / 低。空は「ふつう」として読む。語彙は `ISSUE_PRIORITIES()` が唯一の定義 |
| ラベル (タグ) | どんな種類の仕事かの印。`#` で書く (下) |
| 紐づく文書 | 文書を開くと、その文書の閉じていないやることが本文の上に並ぶ |
| 開始日・期限 | 工程表の棒になる。期限は予定工数から出すこともできる |
| 親 | 大きなやることを分けたとき、元のやることを親にする。輪になる親子は作れない |
| 見積もり | 規模を表す数 |
| 予定工数・実績工数 | 人日。0.5 きざみで書ける。親は子の工数を足し上げて見せる |

やることを押すと、右の欄に**まず読む形で**開く。右上の鉛筆で書き換える。

### やりとりと変更の履歴

- **やりとり** — やることの中で話し合った跡。決めた結果だけでなく、なぜそう決めたかを残すためのもの。
  自分のやりとりは書き直し・消しができる。`@名前` で人を名指しすると、その人に知らせが届く
  (`@` を打つと候補が出る。名簿に無い名前は誰にも届かない)
- **変更の履歴** — 欄がいつ誰にどう変わったか

### 完了・取り消し・捨てる

- **完了にする** と、片づけたことを1つだけ知らせる (重かったもの・長く待たせていたもの・分けたやることの最後の1つ、など。
  起きたことだけを知らせ、くじのような驚かせ方はしない)
- **完了を取り消す** — 早合点で完了にしたものを、やることに戻す
- **捨てる** — すぐには消えず「捨てたもの」に30日置かれ、その間は戻せる。期限を過ぎたぶんは1日1回の片付けで消える
  (片付けはコマンドキューのトリガーに載っているので、`setupCommandQueue()` が要る)
- 捨てたものは、待たずに**完全に消す**こともできる。そのやることに付いたやりとり・ToDo との結び付き・知らせ・
  カード・変更の履歴も一緒に消える (報告との結び付きは外すだけで、報告は残る)
- 一度出した番号は二度出さない。消した #7 の番号が新しいやることに回ると、`closes #7` と書かれた古い確認依頼を
  反映した時点で無関係なやることが完了になってしまうため

### 動きなし

しばらく動いていないやることは色あせ、「◯日動きなし」と出る。段階は既定で 7 / 14 / 30 日で、管理者がチームの
設定 (`stale.steps`) で変えられる。完了したものは色あせない。直すか、完了にするか、捨てるかを決める合図。

## 進捗ボード

| 列 | Git の Projects でいうと | 自動で動くとき |
|---|---|---|
| これから | Backlog | やることを作った |
| 作業中 | In Progress | やることから改訂版を作った・確認依頼を取り下げた |
| 確認中 | In Review | 確認依頼を出した |
| 完了 | Done | 確認依頼を反映した |

- カードは掴んで動かせる。線の出た位置に入る
- 列の「＋」から題名だけ打って足せる
- 手元からは `node agent.mjs board <番号> "In Progress"` で動かせる

## 工程表

開始日から期限までを棒で並べる。上の「工程表」で出る。

- **日 / 週 / 月** で細かさを切り替える (1日の幅 26 / 12 / 4px)。この端末に覚える
- **今日** で今日の位置へ送る。開いたときも今日が見える位置から始まる
- 棒を掴んで動かすと、どの細かさでも1日単位でずれる
- **名前の欄の幅** は、名前の欄と日の並びの間を掴んで左右に引く (120〜480px。キーボードの ←→ でも16px ずつ)。
  二度押しで既定の幅 (220px) に戻る。狭い画面では掴み手を出さない
- 予定工数を書き換えると、棒の長さもそれに合わせる

## 集計

予定と実績の工数を、区切りごとに足し上げて累計も並べる。

- 区切り: 週ごと / 月ごと / 四半期ごと / 半期ごと / 年度ごと。四半期以上は **4月始まりの年度** で切る
- どの日で数えるか: 期限 (いつまでに何人日抱えているか) / 完了日 (いつ何人日消化したか) / 開始日
- 誰の内訳を見るか: チーム全体の合計は誰でも見られる。人ごとの内訳は自分のぶんと、上長として登録されていれば
  その下の人のぶん ([人と工数](people-and-effort.md))

## タグ

どんな種類の仕事かの印。`#文書改訂` のように `#` で書く。

- 最初から入っているもの: 文書改訂 / 問合せ対応 / 定例業務 / 調査 / 会議 / 提出物
- 色を選んで足せる。消すこともできる
- 要望・不具合から積まれたやることには「不具合」「要望」「問合せ対応」が付く

## 下書き

やることの補足に差し込む、よく使う形。差し込んでから書き足す。

- 最初から入っているもの: 作業の段取り / 調べたこと / 打ち合わせの記録
- 自分で作って残せる。消すこともできる

## Google ToDo

自分が担当で、まだ終わっていないやることを Google ToDo に送る。

- 使うには、エディタの「サービス +」から **Tasks** を足す。足していない環境では入口 (「Google ToDo」のボタン) 自体が出ない
- 送る先のリストを選ぶ。期限も一緒に送る
- 送るのは**自分の担当ぶんだけ**。他人のぶんまで流し込むと、自分の予定が読めなくなるため
- ToDo の側で完了にしたものは、次の同期でやることも完了になる。ToDo の側で消したものは結び付きを忘れる

## 手元から

やることは手元の道具からも作れる (`issue` / `issue-update` / `issue-say` / `issue-close` / `board` /
`issue-branch`)。一覧は [手元の道具](agent-kit.md)、命令の形は [コマンドキュー](command-queue.md) にある。
