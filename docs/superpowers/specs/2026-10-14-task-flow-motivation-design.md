# やることを気持ちよく片づける仕組み (取りかかる → 片づける → 続ける)

2026-10-14。利用者から「タスク管理や作業のモチベーション管理・維持の機能を、論文を
調べて考えて。ドーパミンが出るやつ」と頼まれた。狙いは「全部まとめて」。

第1段階 (`docs/superpowers/plans/2026-10-07-motivation.md`) は**チームの前進**に絞った。
今回は**一人ひとりがやることを片づける流れ**を扱う。方針 (点数・レベル・人ごとの順位・
上司向けの個人の監視を作らない) はそのまま引き継ぐ。

## ドーパミンの扱い

ドーパミンは報酬そのものではなく**予想との差**に反応し、確率 50% の報酬で最も強く出る
(Schultz ら 1997, Fiorillo ら 2003)。これをそのまま UI にすると「たまに当たる演出」、
つまりくじになる。ルートボックスと問題ギャンブルの関連 (Zendle & Cairns 2018)、
ダークパターンの整理 (Gray ら 2018, Mathur ら 2019) から、職場の道具では入れない。

**くじで驚かせず、本当に起きたことで驚かせる。** 小分けの最後の1つで親がまとまって
終わる・長く止まっていたものが動く・頼んだ人から「ありがとう」が届く。どれも予想して
いない瞬間に来て、作り物ではない。

## 文献の要点

| 知見 | 出典 | 扱い |
|---|---|---|
| 実行意図 (いつ・どこで・どうする) を決めると目標の達成が上がる (k=94, d=.65) | Gollwitzer & Sheeran 2006; Milkman ら 2011 | ②「最初の一手」「いつやる」 |
| ゴールに近いほど速く動く。済んだぶんを見せると完了率が上がる (34% 対 19%) | Kivetz ら 2006; Nunes & Drèze 2006 | ①「あと◯つ」 |
| 序盤は小目標、終盤は全体を見せるほうが効く。途中の区切りは気を緩めることがある | Huang ら 2017; Amir & Ariely 2008 | ① 親の進み具合 |
| 未完了の記憶の優位 (Zeigarnik) は再現されないが、中断したものを再開したがる (Ovsiankina) | Ghibellini & Meier 2025 | ②「続きから」 |
| 先延ばしは課題の嫌さ・期限の遠さ・自己効力感で決まる | Steel 2007 | ② 小分けと近い区切り |
| 週や月の始まりは目標に取りかかりやすい | Dai, Milkman & Riis 2014 | ② 週はじめの誘い |
| 負荷が高いと簡単なものを選び、難しさで補正すると処理量が下がる | KC ら 2020; Ibanez ら 2018 | **件数だけをほめない** |
| 成功に結び付いた控えめな演出は効くが、派手にすると動機が下がる (n=1,699, 事前登録) | Kao ら 2024; Hicks ら 2019 | ① 印1つだけ |
| 途切れた連続記録を見せると行動が減る。自分のせいだと感じるとさらに減る | Silverman & Barasch 2022; Polivy & Herman 1985 | **毎日の連続記録を作らない** |
| 予告なしの承認で成績が上がる。上位だけの表彰は順位と同じ形 | Bradler ら 2016; Gallus 2017 | ③ 人から人への「ありがとう」 |
| 決まった間隔の休憩は気分を良くするが、完了量は変わらない | Biwer ら 2023; Albulescu ら 2022 | 入れない (優先度が低い) |

本文を確かめられなかったもの (Masicampo & Baumeister 2011, Bono ら 2013) は根拠に使わない。

## 段階

| 段階 | 中身 | 台帳 |
|---|---|---|
| **① 片づける** (この仕様で作る) | 完了の知らせを1つ選んで返す・控えめな演出・「今日片づけたもの」と日報へ写す | 変えない |
| ② 取りかかる | やることに「最初の一手」「いつやる」(任意)・「続きから」・週はじめ/スプリント初日の誘い | `issues` の末尾に列を足す |
| ③ ありがとう | 依頼した人から担当者へ一言。数えない・集計に入れない | 新しい表 |

②③は①を入れて4週測ってから、それぞれ別の仕様にする。

## ① 片づける

### 1. 完了したときに返すもの

`apiCloseFeedback(number)` が、この完了が何だったかを**1つだけ**選んで返す。重ねると
派手になり、どれも残らない。上から順に最初に当てはまったものを返す。

| 順 | `kind` | 当てはまるとき | 知らせ |
|---|---|---|---|
| 1 | `parentDone` | 親を持ち、親の子が全部 `closed` になった | 「#12 規程の改定 の小分けが全部終わりました」と「#12 も完了にする」ボタン |
| 2 | `parentStep` | 親を持ち、親の子にまだ開いているものがある | 「#12 はあと2つ」と細い進み具合 (`done / total`) |
| 3 | `longAwaited` | `createdAt` から `CLOSE_LONG_DAYS()` 日以上たっている | 「3週間越しのものが片づきました」(日数を週・日の言い方に直す) |
| 4 | `heavy` | `points >= CLOSE_HEAVY_POINTS()` または `plannedHours >= CLOSE_HEAVY_HOURS()` | 「大きいものが1つ終わりました」 |
| 5 | `team` | どれにも当てはまらない | いまの「今週チームで◯件目」(`apiProgress` の値) |

- 定数は `CLOSE_LONG_DAYS() = 14`、`CLOSE_HEAVY_POINTS() = 5`、`CLOSE_HEAVY_HOURS() = 4`。
  入れたあと4週で見直す
- **親は勝手に閉じない。** 子が全部終わっても親に残りの仕事があることがある。ボタンで
  本人に決めさせる (押すと `apiIssueClose(親)` を呼び、親についても同じ知らせを返す)
- 捨てた子 (`archivedAt` あり) は親の数に入れない。捨てたものが「残り」として居座ると
  永遠に終わらない
- 親が既に閉じているときは 1・2 に当てはめない (3 以下へ進む)
- 読めない日付 (`plainDate` で空になるもの) は 3 に当てはめない
- 返す形: `{kind, number, title, parent?: {number, title, done, total}, days?, weekClosed}`。
  変換は `src/core/Plain.js` を通す

### 2. 演出

- 帯 (`showSnack`) の左に印を1つ置く。チェックの線が 300ms で描かれる (SVG の
  `stroke-dashoffset`)。`parentStep` では帯の中の進み具合が前の値から1段伸びる
- 紙吹雪・音・揺れは入れない
- `prefers-reduced-motion: reduce` では動かさず、描き終えた形で出す
- 「前進の知らせを出す」を切っている人には、いまと同じ素の帯だけを出す
  (`apiCloseFeedback` も呼ばない)
- `parentDone` のボタンは帯の中に置き、帯が消えるまでの時間を延ばす (押す間が要る)

### 3. ホームの「今日片づけたもの」

`apiMyToday()` が**本人のぶんだけ**返す。ホームのカードに1枚足す。

載せるもの (東京の今日、`motivationDay_` で区切る):

- `state === 'closed'` で `closedAt` が今日のやることのうち、`issues.assignee`
  (カンマ区切り) に自分が入っているもの
- 同じく担当が空のもののうち、`change_log` で `target = 'issue:N'`・`action = 'close'` の
  最後の行の `actor` が自分のもの
- `state === 'merged'` で `mergedAt` が今日の、自分が `author` の確認依頼

- 完了を取り消したものは `state` が戻るので自然に消える
- 並べるのは番号と題名だけ。件数を大きく出さない
- 0件のときは「これから」。責める書き方をしない
- **「日報にコピー」** で `✅今日` の節の形をクリップボードに写す:

  ```
  ✅今日
  - #12 規程の改定
  - 確認依頼 #7 細則の見直し を正式版に反映
  ```

- 「前進の知らせを出す」を切っていると出さない (ホームのほかのカードと同じ)
- 台帳は表ごとに1回だけ読む。行ごとに `dbFindOne` をしない

### 4. 作り

| 場所 | 足すもの |
|---|---|
| `src/core/Motivation.gs` | `CLOSE_*` 定数・`closeFeedback_(number, now)`・`myToday_(email, now)` |
| `src/Main.gs` | `apiCloseFeedback(number)`・`apiMyToday()`。後者は開いている本人のアドレスだけを渡す |
| `src/ui/app.js.html` | `celebrateProgress` の `close` 3か所を番号を渡す形に。`makeTodayCard`。帯の印 |
| `src/ui/app.css.html` | 帯の印・進み具合。既存トークンのみ |

- `myToday_` は末尾 `_` にする。アドレスを受けるので、画面から呼べるとほかの人の
  一日を覗ける (`motivationMilestones_` と同じ理由)
- `apiCloseFeedback` が失敗しても、いまの帯は必ず出す (`celebrateProgress` の今の作りと同じ)
- 返事が来た時点で別の画面に移っていても帯は出してよい (帯は画面に属さない)。
  ホームのカードの描き直しは、ホームを開いているときだけ

### 5. テスト

- `test/motivation.test.js` (または新しい `test/closefeedback.test.js`)
  - 1〜5 の各分岐。**作る順を期待の逆にする** (偶然一致しないように)
  - 捨てた子を数えない・親が閉じていると 1・2 に入らない・読めない日付
  - `myToday_`: 担当に入っている・担当が空で自分が閉じた・他人が閉じた・取り消した・
    昨日の・自分の確認依頼の反映
- `test/phase4-edit.test.js` の「画面に渡せる形か」に2つの API を足す
- `test/component.test.js` で実際に押す: 完了 → 帯に「あと2つ」、最後の子 → 「#12 も
  完了にする」を押すと親も閉じる、知らせを切ると素の帯、「日報にコピー」の字
- 直したら、元に戻して落ちることを確かめる

### 6. 測り方

入れる前の4週と、入れたあとの4週を比べる。人を追わない形で数える。

- チームの週ごとの完了件数 (`apiProgress`)
- 完了したやることのうち、`parentDone`・`longAwaited`・`heavy` に当たったものの割合
  (件数だけ増えて重いものが減っていないか。KC らの害を見張る)

## やらないこと

- くじ・ランダムな報酬・確率で変わる演出
- 毎日の連続記録 (休みが罰になる)
- 片づけた件数を人ごとに並べる・上司に見せる
- 派手な演出・音
- ポモドーロのタイマー
