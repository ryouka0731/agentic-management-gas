# やることを気持ちよく片づける仕組み (取りかかる → 片づける → 続ける)

2026-10-14。利用者から「タスク管理や作業のモチベーション管理・維持の機能を、論文を
調べて考えて。ドーパミンが出るやつ」と頼まれた。狙いは「全部まとめて」。

第1段階 (`docs/superpowers/plans/2026-10-07-motivation.md`) は**チームの前進**に絞った。
今回は**一人ひとりがやることを片づける流れ**を扱う。

**第1段階の「点数・レベル・順位は入れない」は、利用者の判断で改めた。** 設計の途中で
「ゲーミフィケーションも加えたい」「ポイント・レベル・順位も」「順位を入れるなら上位者
だけ」と頼まれた。文献の害 (順位の下位が晒しになる・件数を追わせる・監視に見える) は
消えないので、守りを付けて入れる (「① の 6. ゲーミフィケーション」)。上司向けの個人の
監視・人事評価への結び付けを作らない方針はそのまま引き継ぐ。

## ドーパミンの扱い

ドーパミンは報酬そのものではなく**予想との差**に反応し、確率 50% の報酬で最も強く出る
(Schultz ら 1997, Fiorillo ら 2003)。これをそのまま UI にすると「たまに当たる演出」、
つまりくじになる。ルートボックスと問題ギャンブルの関連 (Zendle & Cairns 2018)、
ダークパターンの整理 (Gray ら 2018, Mathur ら 2019) から、職場の道具では入れない。

**くじで驚かせず、本当に起きたことで驚かせる。** 小分けの最後の1つで親がまとまって
終わる・長く止まっていたものが動く・頼んだ人から「ありがとう」が届く。どれも予想して
いない瞬間に来て、作り物ではない。

## 文献の要点

| 知見 | 出典 | 扱い |
|---|---|---|
| 実行意図 (いつ・どこで・どうする) を決めると目標の達成が上がる (k=94, d=.65) | Gollwitzer & Sheeran 2006; Milkman ら 2011 | ②「最初の一手」「いつやる」 |
| ゴールに近いほど速く動く。済んだぶんを見せると完了率が上がる (34% 対 19%) | Kivetz ら 2006; Nunes & Drèze 2006 | ①「あと◯つ」 |
| 序盤は小目標、終盤は全体を見せるほうが効く。途中の区切りは気を緩めることがある | Huang ら 2017; Amir & Ariely 2008 | ① 親の進み具合 |
| 未完了の記憶の優位 (Zeigarnik) は再現されないが、中断したものを再開したがる (Ovsiankina) | Ghibellini & Meier 2025 | ②「続きから」 |
| 先延ばしは課題の嫌さ・期限の遠さ・自己効力感で決まる | Steel 2007 | ② 小分けと近い区切り |
| 週や月の始まりは目標に取りかかりやすい | Dai, Milkman & Riis 2014 | ② 週はじめの誘い |
| 負荷が高いと簡単なものを選び、難しさで補正すると処理量が下がる | KC ら 2020; Ibanez ら 2018 | **件数だけをほめない** |
| 成功に結び付いた控えめな演出は効くが、派手にすると動機が下がる (n=1,699, 事前登録) | Kao ら 2024; Hicks ら 2019 | ① 印1つだけ |
| 途切れた連続記録を見せると行動が減る。自分のせいだと感じるとさらに減る | Silverman & Barasch 2022; Polivy & Herman 1985 | **毎日の連続記録を作らない** |
| 予告なしの承認で成績が上がる。上位だけの表彰は順位と同じ形 | Bradler ら 2016; Gallus 2017 | ③ 人から人への「ありがとう」 |
| 決まった間隔の休憩は気分を良くするが、完了量は変わらない | Biwer ら 2023; Albulescu ら 2022 | 入れない (優先度が低い) |

本文を確かめられなかったもの (Masicampo & Baumeister 2011, Bono ら 2013) は根拠に使わない。

## 段階

| 段階 | 中身 | 台帳 |
|---|---|---|
| **① 片づける** (この仕様で作る) | 完了の知らせを1つ選んで返す・控えめな演出・「今日片づけたもの」と日報へ写す | 変えない |
| ② 取りかかる | やることに「最初の一手」「いつやる」(任意)・「続きから」・週はじめ/スプリント初日の誘い | `issues` の末尾に列を足す |
| ③ ありがとう | 依頼した人から担当者へ一言。数えない・集計に入れない | 新しい表 |

②③は①を入れて4週測ってから、それぞれ別の仕様にする。

## ① 片づける

### 1. 完了したときに返すもの

`apiCloseFeedback(number)` が、この完了が何だったかを**1つだけ**選んで返す。重ねると
派手になり、どれも残らない。上から順に最初に当てはまったものを返す。

| 順 | `kind` | 当てはまるとき | 知らせ |
|---|---|---|---|
| 1 | `parentDone` | 親を持ち、親の子が全部 `closed` になった | 「#12 規程の改定 の小分けが全部終わりました」と「#12 も完了にする」ボタン |
| 2 | `parentStep` | 親を持ち、親の子にまだ開いているものがある | 「#12 はあと2つ」と細い進み具合 (`done / total`) |
| 3 | `longAwaited` | `createdAt` から `CLOSE_LONG_DAYS()` 日以上たっている | 「3週間越しのものが片づきました」(日数を週・日の言い方に直す) |
| 4 | `heavy` | `points >= CLOSE_HEAVY_POINTS()` または `plannedHours >= CLOSE_HEAVY_DAYS()` (plannedHours は人日) | 「大きいものが1つ終わりました」 |
| 5 | `team` | どれにも当てはまらない | いまの「今週チームで◯件目」(`apiProgress` の値) |

- 定数は `CLOSE_LONG_DAYS() = 14`、`CLOSE_HEAVY_POINTS() = 5`、`CLOSE_HEAVY_DAYS() = 1` (単位は人日。plannedHours は列の名前に反して人日で持っている)。
  入れたあと4週で見直す
- **親は勝手に閉じない。** 子が全部終わっても親に残りの仕事があることがある。ボタンで
  本人に決めさせる (押すと `apiIssueClose(親)` を呼び、親についても同じ知らせを返す)
- 捨てた子 (`archivedAt` あり) は親の数に入れない。捨てたものが「残り」として居座ると
  永遠に終わらない
- 親が既に閉じているときは 1・2 に当てはめない (3 以下へ進む)
- 読めない日付 (`plainDate` で空になるもの) は 3 に当てはめない
- 返す形: `{kind, number, title, parent?: {number, title, done, total}, days?, weekClosed}`。
  変換は `src/core/Plain.js` を通す

### 2. 演出

- 帯 (`showSnack`) の左に印を1つ置く。チェックの線が 300ms で描かれる (SVG の
  `stroke-dashoffset`)。`parentStep` では帯の中の進み具合が前の値から1段伸びる
- 紙吹雪・音・揺れは入れない
- `prefers-reduced-motion: reduce` では動かさず、描き終えた形で出す
- 「前進の知らせを出す」を切っている人には、いまと同じ素の帯だけを出す
  (`apiCloseFeedback` も呼ばない)
- `parentDone` のボタンは帯の中に置き、帯が消えるまでの時間を延ばす (押す間が要る)

### 3. ホームの「今日片づけたもの」

`apiMyToday()` が**本人のぶんだけ**返す。ホームのカードに1枚足す。

載せるもの (東京の今日、`motivationDay_` で区切る):

- `state === 'closed'` で `closedAt` が今日のやることのうち、`issues.assignee`
  (カンマ区切り) に自分が入っているもの
- 同じく担当が空のもののうち、`change_log` で `target = 'issue:N'`・`action = 'close'` の
  最後の行の `actor` が自分のもの
- `state === 'merged'` で `mergedAt` が今日の、自分が `author` の確認依頼

- 完了を取り消したものは `state` が戻るので自然に消える
- 並べるのは番号と題名だけ。件数を大きく出さない
- 0件のときは「これから」。責める書き方をしない
- **「日報にコピー」** で `✅今日` の節の形をクリップボードに写す:

  ```
  ✅今日
  - #12 規程の改定
  - 確認依頼 #7 細則の見直し を正式版に反映
  ```

- 「前進の知らせを出す」を切っていると出さない (ホームのほかのカードと同じ)
- 台帳は表ごとに1回だけ読む。行ごとに `dbFindOne` をしない

  ホームのカードの描き直しは、ホームを開いているときだけ

### 6. ゲーミフィケーション (ポイント・レベル・週の上位)

利用者の判断で入れる。文献の害に対して次の守りを付ける。

| 害 | 出典 | 守り |
|---|---|---|
| 件数を追わせると簡単なものから手を付ける | KC ら 2020 | 件数ではなく**重さ**で付ける |
| 職場の順位の下位は晒しと受け取られる | Jia ら 2017 | **上位3人だけ**出す。上位に入らない人はどこにも出ない |
| 通算の順位は古参が居座る | Jia ら 2017 | **週ごと**に数え直す (週はじめはやり直しやすい: Dai ら 2014) |
| 監視に見えるとストレスが増える | Ravid ら 2023 | 既定オフ・参加は本人が選ぶ・評価に使わないと画面に書く |
| 点数は量を増やすが内発的動機は上げない | Mekler ら 2017 | ①の知らせ (本当に起きたこと) を主にし、点数は添えるだけ |

#### ポイント

**台帳から数え、どこにも保存しない** (`ScrumView.js` と同じく、手で書く数は必ずずれる)。
完了を取り消せば消えるので、閉じる・開くを繰り返しても増えない。

| こと | ポイント | いつのものとして数えるか |
|---|---|---|
| やることを完了にする (`state === 'closed'`) | 1 | `closedAt` |
| 　重い (①の `heavy` の条件) | +2 | 同上 |
| 　長く止まっていた (①の `longAwaited` の条件) | +2 | 同上 |
| 　親の子の最後で、親の子が全部終わっている (①の `parentDone` の条件) | +1 | 同上 |
| ほかの人の確認依頼に承認・差し戻しを出す (`reviews.state` が `approve` / `request_changes`。自分の依頼は除く) | 1 | 確認の日時。同じ依頼には1人1回 |
| 自分が出した確認依頼が反映された (`state === 'merged'`) | 2 | `mergedAt` |

- 担当が複数いるやることは**頭数で割る** (工数と同じ数え方。割らないと人ごとの合計を
  足しても全体に戻らない)。担当が空なら `change_log` で閉じた人に付ける
- `parentDone` の条件は**いまの**子の状態で見る (後から子が開き直されたら +1 は消える)
- `heavy` / `longAwaited` は①の定数をそのまま使う。①と食い違わせない
- ①の完了の知らせに本人の取りぶんを「(+1)」のように添える (`apiCloseFeedback` が `points` を返す。固定値ではなく、重さと頭数で変わる。例: ふつうの完了 +1、2人で担当 +0.5)

#### レベル

- それまでのポイントの合計から決める。レベル n に必要な合計は `5 × n × (n + 1) / 2`
  (1→5, 2→15, 3→30 …)。上がるほど遠くなる
- **本人にだけ**見せる
- **下がらない。** 取り消しで合計が減っても、`PropertiesService.getUserProperties()` に
  覚えた最高を下回らない。上がった瞬間は①の知らせに「レベル4になりました」を添える
  (ほかの知らせの代わりにはしない)
- **見せたことを覚えるのは、画面が実際に見せたときだけ** (`apiGameLevelSeen(n)`)。
  ホームのカードがレベルを描いたとき・帯が「レベル N になりました」を出したときに
  覚える。返事を作った時点で覚えると、画面がその返事を捨てたとき (帯が替わっていた等)
  一度も見えないまま消え、逆にホームで見せたレベルを次の完了で「なりました」と言う。
  実際に届いているレベルより上は覚えない

#### 週の上位

- 月曜〜日曜 (東京) の週のポイントで**上位3位まで**をホームに出す。同点は同じ順位で並べる
  (3位が同点で複数いれば全員)
- 載るのは「順位に参加する」を選んだ人だけ。**既定は不参加**。0点は載らない
- 名前は表示名 (`memberNames` で一度に引く)。点数も添える
- 自分が上位にいないとき、自分の順位は**出さない** (出すと「◯位」という下位の印になる)。
  自分の週のポイントだけは本人に見せる

#### オン・オフ

- スクリプトプロパティ `GAME_ENABLED` が `'true'` のときだけオン。**既定はオフ**。
  切り替えは管理者 (`repoAssertAdmin_`)、画面は「設定」。スクラムの切り替えと同じ形
- オフのあいだ、ポイント・レベル・順位の API は空を返し (断らない。ホームのカードが
  落ちないように)、画面に何も出さない
- 参加者の一覧はスクリプトプロパティ `GAME_PLAYERS` (アドレスの JSON 配列)。書き換えは
  `dbWithLock_` の中で「読む → 足す/外す → 書く」。分けると同時の2人のどちらかが消える
- 「前進の知らせを出す」を切った人には、自分のポイント・レベル・順位のカードも出さない

#### 見せない場所

- 使われ方・工数の集計・書き出し・メールの知らせには入れない
- 順位のカードとレベルの欄に「人事の評価には使いません」と書く
- 「人に関わる数は本人と部下のぶんだけ見せる (`memberVisibleTo`)」の**唯一の例外**が
  週の上位である。実装のときに CLAUDE.md の「画面から呼べる関数」の節へその旨を書く

#### 作り (足すもの)

| 場所 | 足すもの |
|---|---|
| `src/core/Game.gs` (新規) | `GAME_ENABLED` の読み書き・参加の出し入れ・`gamePointsByPerson_(from, to)`・`gameLevel(total)` |
| `src/core/Motivation.gs` | `closeFeedback_` が `points` と `levelUp` を返す |
| `src/Main.gs` | `apiGameState()` (オンか・自分の合計/週/レベル/参加しているか)・`apiGameLevelSeen(n)`・`apiGameTop()`・`apiGameJoin(bool)`・`apiSetGameEnabled(bool)` |
| `src/ui/app.js.html` | ホームの「週の上位」「自分のレベル」カード・設定の切り替え・自分まわりの「順位に参加する」 |

`gamePointsByPerson_` は `issues` / `reviews` / `pulls` / `change_log` を1回ずつ読んで
人ごとに足す。行ごとに `dbFindOne` をしない。

#### テスト

- ポイント表の各行・頭数で割る・担当が空なら閉じた人・取り消すと消える・自分の依頼への
  確認は数えない・同じ依頼に2回確認しても1
- レベルの境目 (4→1未満, 5→1, 15→2)・下がらない
- 週の上位: 上位3位まで・同点・不参加は載らない・0点は載らない・先週のぶんは入らない・
  4位以下の人に自分の順位が返らない
- オフのとき API が空を返す・管理者でないと切り替えられない
- 参加の出し入れが鍵の中で行われる (`test/numbering.test.js` と同じく鍵を差し替えて確かめる)
- 「画面に渡せる形か」に4つの API を足す
- component テストで設定の切り替え → ホームにカードが出る、を押して確かめる

### 7. 測り方

入れる前の4週と、入れたあとの4週を比べる。人を追わない形で数える。

- チームの週ごとの完了件数 (`apiProgress`)
- 週の上位に参加した人の割合と、参加をやめた人の数 (やめた人が多ければ順位を見直す)
- 完了したやることのうち、`parentDone`・`longAwaited`・`heavy` に当たったものの割合
  (件数だけ増えて重いものが減っていないか。KC らの害を見張る)

## やらないこと

- くじ・ランダムな報酬・確率で変わる演出
- 毎日の連続記録 (休みが罰になる)
- 件数で付けるポイント・通算の順位・上位以外の順位・上司向けの個人の集計
- ポイントやレベルを人事評価に結び付けること
- 派手な演出・音
- ポモドーロのタイマー
