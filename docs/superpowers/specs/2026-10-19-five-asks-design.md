## A. 文書プレビューの全画面表示と、全画面プレビューのリンク (#17)

### 全画面
- 文書を読んでいるとき (`#panel-content`、読むモード)、題名の並びに「全画面」のボタン `#doc-full-btn`
  (印は既存の `makeIcon` にあるもの。無ければ字だけ)
- 押すと `document.body` に `doc-full` を付ける。CSS で、ヘッダー・左の行き先・右のペイン・掴み手・
  文書の上の操作の並びを隠し、`#viewer` を画面いっぱいにする。題名と「全画面を閉じる」だけを上に細く残す
- **ブラウザの Fullscreen API は使わない。** Apps Script の Web アプリは iframe の中で動き、`allow="fullscreen"`
  が無いので断られる。CSS で広げる形だけにする
- Esc・閉じるボタン・別の文書やタブへ移ったときに抜ける (`switchTab` が抜ける)。直すモードには入れない
  (全画面のときは「直す」を出さない)

### 全画面プレビューのリンク
- 全画面のボタンの隣に「リンクをコピー」`#doc-link-btn`。この Web アプリの URL に `?doc=<fileId>&full=1` を
  付けたものを作る
- この Web アプリの URL はサーバの `apiAppUrl()` が `ScriptApp.getService().getUrl()` で返す (画面は自分の
  URL を知らない。iframe の中なので `location` は使えない)
- コピーは `navigator.clipboard.writeText` を試し、断られたら (iframe では断られることがある) 既存の
  `makeCopyRow` で字を見せて選べるようにする。帯で「コピーしました」
- **開く側:** 起動時に `google.script.url.getLocation(cb)` で `parameter.doc` / `parameter.full` を読む。
  `doc` は文書の一覧 (`allFiles`) に**ある fileId のときだけ**開く (`openDocById`)。無ければ「この文書は
  見られないか、登録されていません」と帯で知らせてホームのまま。`full=1` なら開いたあと全画面にする
- リンクは文書を見られる人にだけ意味がある (開いた人の権限で読む)。リンクに秘密は入れない
- `doGet` は今までどおり。`?p=` の検査も変えない

### テスト
- component: ボタンで全画面になり Esc で戻る / 別タブへ移ると抜ける / リンクに `?doc=…&full=1` が入る /
  `getLocation` が `doc` を返すとその文書が全画面で開く / 一覧に無い id は開かない
- `test/dom.js` に `google.script.url.getLocation` の疑似と `apiAppUrl` の既定 (1回だけ)
- `apiAppUrl` を「画面に渡せる形か」に足す

## B. 工程表のペインを動かせるようにし、使い勝手を上げる (#16)

- **名前の欄の幅を掴んで変える。** 名前の欄と日の並びの間に掴み手 (`.resizer` の作法に従う:
  `pointercancel` と `window` 側でも外す、`min-width: 0`)。幅は `--gantt-name-w` を変え、`localStorage`
  (`ganttNameW`) に覚える。120〜480px。キーボードでも ←→ で 16px ずつ (掴み手に `role="separator"`
  `aria-orientation="vertical"` `tabindex="0"` `aria-valuenow`)。ダブルクリックで既定 (220px) に戻す
- **表示の細かさ。** 「日 / 週 / 月」の切り替え (`#gantt-zoom`、既存の札の形のボタン群)。1日の幅を
  26 / 12 / 4 px にする (`COL` を変える)。週・月では日の見出しを間引き、月の見出しは残す。`localStorage`
  (`ganttZoom`) に覚える
- **今日へ。** 開いたとき今日が見える位置まで横に送る (今日の線が左から 1/3 に来る)。「今日」のボタンでも送る
- 掴んで動かす棒の操作 (`makeBarDraggable`) は、どの細かさでも 1 日単位でずれる (`COL` を使って日に直す)
- 狭い画面 (767px 以下) では掴み手を出さず、名前の欄は 140px
- `ganttLayout` (サーバと画面の両方) は変えない。変えるなら両方と `test/ui-parity.test.js`

### テスト
- component: 掴んで動かすと幅が変わり覚える / 範囲で止まる / キーボードで動く / ダブルクリックで戻る /
  細かさを変えると日の幅が変わり覚える / 細かさを変えても棒を掴んで1日ずらせる / 今日へ送る
  (`scrollLeft` が今日の位置に合う)

## C. ゲーミフィケーションを広げる (#15)

既にある「ポイントとレベル」(既定オフ・参加は本人・週の上位3人だけ・アドレスを返さない・ポイントは台帳から
数えて保存しない) の上に足す。**守りは1つも崩さない。連続日数は出さない。**

- **確認にもポイント。** 他人の確認依頼に返したやりとり (承認・差し戻し・コメント付きの確認) 1件 = 1点。
  自分の依頼への確認は数えない。同じ依頼に何度返しても、その依頼では1日1点まで (数稼ぎをさせない)。
  `reviews` から数える (`gamePointsByPerson_` に足す)。週の上位にも入る
- **称号 (バッジ)。** 本人にだけ見せる (`apiGameState` の `badges`)。台帳から数える。保存しない。
  - はじめの一歩: やることを1件片づけた
  - 10件・50件・100件片づけた
  - 重いやること (`motivationIsHeavy_`) を片づけた
  - 待たせていたもの (`CLOSE_LONG_DAYS` 以上) を片づけた
  - 確認を10件返した
  - 分けたやることを最後まで片づけた
  得た日付 (その条件を満たした日) を添える。ホームのゲームのカードに、得たものを並べ、まだのものは薄く
  「あと N 件」と出す (次の目標が見える)
- **先週のチーム。** チーム全員の先週のポイントの合計 (名前なし) を、先々週の合計と比べて棒で見せる。
  参加していない人のポイントも合計には入る。個人が特定されないよう、次を守る (確認依頼 #27 の指摘で改めた)
  - **終わった週だけ使う。** 今週の合計は動くので、読むたびの差から1人の増えた分が見える
  - **週ごとに、見る人のほかに2人以上ポイントのあった週だけ数を出す。** そうでなければその週は出さない
    (見る人は自分の点を引けるので、ほかに1人だとその人の数がそのまま見える)。先週が出せなければ欄ごと
    出さず、先々週が出せなければ先週の合計だけ出して棒は出さない
  - **見る人が分からないときは何も出さない** (全員を「ほかの人」と数えてしまう)

### テスト
- `test/game.test.js`: 確認のポイント (自分の依頼は0・同じ依頼は1日1点) / 称号の条件と日付 / チームの
  合計に名前もアドレスも入らない / 今週は返さない / 見る人のほかに1人だけの週は出さない / 見る人が空なら
  何も返さない / オフなら何も返さない
- component: 称号の並びと「あと N 件」/ チームの棒

## D. 実態に即した仕事の自動化・効率化の助言 (#14)

ホームに「改善のヒント」のカード。**本人のデータとチームの合計だけから** 決まった規則で出す (外部 API は
使わない。AI に問い合わせない)。多くて3件。1件ごとに「なぜそう言うか (数字)」と「次にすること (ボタン)」。

`homeAdvice_(email, now)` (`src/core/Home.gs`) が規則を順に当て、当たったものを重みの順に返す:

| 規則 | 条件 (本人) | 言うこと | ボタン |
|---|---|---|---|
| 期限切れが溜まっている | 期限切れの担当が3件以上 | 期限を見直すか、分けるか、手放す | 期限切れで絞ったやること |
| 抱えすぎ | 作業中 (In Progress) の担当が5件以上 | 手を付けるのを3件までに絞ると早く終わる | ボードを開く |
| 確認を待たせている | 自分宛ての確認が3日以上返っていない | 先に返すと相手が進める | 確認依頼を開く |
| 同じ作業の繰り返し | 30日で同じタグ (または題名の先頭の語) のやることを5件以上作った | ひな形にするか、手元の道具で自動化できる | そのタグで絞ったやること |
| 見積もりと実際のずれ | 30日で片づけた担当のうち、工数を書いたものの半分以上が予定の倍以上かかった (`startDate`〜`closedAt` の日数 vs `ganttDaysForEffort(effort)`) | 見積もりを大きめにするか、分けて小さくする | 工程表を開く |
| 報告の同じ種類 (管理者のみ) | 30日で「使い方が分からない」の報告が3件以上 | 使い方に書き足すと減る | 要望・不具合を開く |

- 出さない日付・理由は端末に覚える (`localStorage` の `adviceHidden`、id と週)。「今週は出さない」で隠す
- 当たる規則が無ければカードごと出さない
- **人の名前・他人の数は出さない。** 報告の規則は件数だけ (誰が出したかは言わない)
- `apiHomeSummary` に `advice` を足す (`plain*` を通す)
- 規則の言葉と閾値は `ADVICE_RULES()` が唯一の定義

### テスト
- `test/advice.test.js` (疑似GAS): 規則ごとに当たる・当たらない境目 / 重みの順で3件まで / 他人のやることは
  数えない / 管理者でなければ報告の規則は出ない / 返す形に名前・アドレスが無い
- component: カードが出る / ボタンで絞った一覧へ / 「今週は出さない」で消え、覚える

## E. 手元の道具を強くする (#13)

手元から番頭に頼めることを足す。**頼んだ本人のぶんだけ返す。** 命令の本人は `commandOwner_` (マイドライブは
ファイルの持ち主、共有ドライブは最後に書いた人)。分からなければ断る (他人のぶんを返さない)。

| 道具の命令 | 番頭の命令 (`COMMAND_OPS`) | 返すもの |
|---|---|---|
| `node agent.mjs mine` | `homeMine` | あなたの番 (`homeMyTurn_` と同じ: 待っている確認・戻ってきたもの・期限) |
| `node agent.mjs advice` | `homeAdvice` | D の改善のヒント (同じ `homeAdvice_`) |
| `node agent.mjs search <語…>` | `searchIndex` | 横断検索の一覧を手元で絞る (`searchFilter` と同じ合わせ方を手元に写す。題名・番号・状態だけ) |
| `node agent.mjs report [today]` | `reportDraft` | 今日の日報の下書き (`reportParts_` / `REPORT_TEMPLATES()` の本人の形) |
| `node agent.mjs doctor` | (番頭に頼まない) | 設定・キューの置き場・最後の返事までの時間・道具の版・フックの有無を点検して、直し方を出す |

- 番頭の命令は `runCommand_(cmd, by)` の `by` を使う。`by` が空なら `'命令を置いた人が分かりません'` で断る
- `kit/AGENTS.md` (zip の中で CLAUDE.md にもなる) と `node agent.mjs` のヘルプに足す。banto-track の
  スキルに「始める前に `mine` で自分の番を見る」を足す
- `AGENT_KIT_VERSION()` を上げる (1.9.0)。`src/KitFiles.gs` は焼き直す

### テスト
- `test/agentkit.test.js` / `test/kit-*.test.js`: 命令の対応表 / 本人が分からないと断る / 他人のぶんを返さない /
  `search` の合わせ方が画面の `searchFilter` と同じ答え (`ui-parity` の作法) / `doctor` が置き場の無いとき・
  返事が来ないときに直し方を出す
