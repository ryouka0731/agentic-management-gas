# ホーム (トップページ) 設計

2026-10-14。利用者の依頼:「トップページを設けて諸々のサマリが見れるように。GitHub の草の
ようにアクティビティがチャートで見れたり」「文書タブに文書以外の情報を出すのは不自然」
「日報のフォーマットはカスタムしたり選べるように」。

## 1. 決めたこと (利用者に確かめた)

| 問い | 決めたこと |
|---|---|
| 草は誰のぶんか | **自分の草** (本人にだけ見える) と **チームの草** (全員の合計・人ごとに分けない) |
| 1マスの濃さ | **前に進めた行いの数** (下の表)。開いた・見た・やりとりの書き込みは数えない |
| 並べるもの | あなたの番・前進カード一式・全体の数・最近の動き |
| 最初の画面 | **ホーム**。文書タブは文書の一覧だけに戻す |
| サーバの分け方 | 草だけ別の API。ほかの新しいものは1つにまとめ、前進カードは既存の API のまま |
| 最近の動き | **人の名前を出さない** (誰が何をしたかの流れは監視と受け取られやすい) |
| 日報の形 | **ひな形から選ぶ + 差し込みで自分の形を書ける**。本人ごとに覚える |

守り (以前の決めごとと文献):

- 人に関わる数は本人と部下のぶんだけ (CLAUDE.md)。草は本人のぶんとチームの合計だけで、
  **部下を含めて他人の草は出さない**。週の上位 (既存の唯一の例外) は増やさない
- **連続日数・最長記録は出さない。** 途切れたときに意欲が下がる (Silverman & Barasch 2022)。
  草の下に出す字は「直近1年で N 件」だけ
- 数はすべて台帳から数え、どこにも保存しない (キャッシュもしない。自分の草を数えるのに同じ表を読むので、チームだけ置いても軽くならない)

## 2. 画面

### 2.1 行き先

- 左のメニューのいちばん上に **ホーム** (`data-tab="home"`)。スマホの下の帯も先頭にホーム
- 開いたときは `switchTab('home')`。返事を待たずにすぐ出す (2026-10-14 に直した「開いた直後に
  ホームへ戻される」と同じ理由。返事を待ってから切り替えない)
- 文書を閉じる戻り道 (`crumbBack`) は今までどおり文書の一覧へ戻す
- 「はじめの案内をもう一度出す」はホームへ移る

### 2.2 ホームの並び (上から)

1. **はじめに** (閉じるまで)。説明と「文書を登録する」「手元から動かす道具を落とす」。
   文書タブから移す。流れの数はここから外し、4 の「全体の数」に寄せる (同じ数を2回出さない)
2. **あなたの番** (2.3)
3. **草**: あなた / チーム の2段 (2.4)
4. **前進**: 今日片づけたもの (日報) ・ポイントとレベル・チームの前進・はじめの5歩。
   文書タブから移す。前進の知らせを止めている人には出さない (今までどおり)
5. **全体の数** と **最近の動き** を横に並べる (狭い画面では縦)

### 2.3 あなたの番

種類ごとに5件まで。超えたぶんは「ほか N 件」で一覧へ送る。押すとそのものを開く。

| 種類 | 条件 |
|---|---|
| 確かめてほしい確認依頼 | 状態が open / approved で、自分が確認者に入っていて、自分の最後の判断が無いか古い (承認のあと中身が変わった) |
| 戻ってきた確認依頼 | 自分が出した open / approved の依頼で、差し戻しが残っている |
| 期限のやること | 自分が担当の未完了 (捨てたものを除く) で、期限切れか3日以内。期限の早い順 |

何も無ければ「いまあなたを待っているものはありません」。判断の新旧は `prDecisions_` と同じ
規則で数えるが、**依頼ごとに表を読まない** (reviews と pulls を1回ずつ読んで引く表を作る)。

### 2.4 草

- 直近 **53週 × 7日**。行は **月曜〜日曜**。いちばん右の列が今週。上に月の見出し
- 色は5段。0件は `--line`、1件以上はその年の分布の4分位で4段 (`--accent` の濃さ)。
  既存トークンだけを使う
- 指を置く・フォーカスすると「10月14日 (火) 3件」。図に `role="img"` と要約の `aria-label`
- 狭い画面では横に流し、開いたときは右端 (今週) を見せる
- 下に「直近1年で N 件」(自分のぶんだけ)。**連続日数・最長記録は出さない**

数える行い:

| 行い | 台帳 | 自分の草に数える人 | 日 |
|---|---|---|---|
| 変更を記録した | `commits` | `author` | `timestamp` |
| やることを完了した | `issues` (`state = closed`) | `motivationCredited_` (担当、空なら閉じた人) | `closedAt` |
| 確認依頼を出した | `pulls` | `author` | `createdAt` |
| 承認・差し戻した | `reviews` (`approve` / `request_changes`) | `reviewer` (自分の依頼への判断は数えない) | `at` |
| 正式版に反映した | `pulls` (`state = merged`) | `author` | `mergedAt` |

- 日は東京の日付 (`motivationDay_`)。読めない日付の行は飛ばす (例外にしない)
- **チームの草は1つの行いを1回。** 担当が2人のやることを完了しても1
- 完了を取り消したもの (`state` が closed でない) は数えない
- 反映は、依頼を出した人の「反映した」1件と、反映で残る変更の記録 (反映した人) 1件の両方に数える (どちらも行い)

### 2.5 全体の数・最近の動き

- **全体の数**: やること・改訂版・確認依頼・正式版の数を流れの形で。既存の `apiOverview` を使う
- **最近の動き**: チームで起きたことを新しい順に10件。名前は出さず「2時間前」を添える。押すと開く
  - 出すもの: 正式版への反映 / やることの完了 / 確認依頼を出した / 文書を登録した (`files.registeredAt`、正式版だけ)
  - 変更の記録は数が多く流れるので出さない。捨てたやることは出さない

### 2.6 日報

「今日片づけたもの」のカードに「日報にコピー」・形を選ぶ欄・「自分の形を直す」。

ひな形 (サーバの `REPORT_TEMPLATES()` が唯一の定義。画面は取れなかったときの控え):

| key | 名前 | 中身 |
|---|---|---|
| `three` (既定) | 3節 | `✅今日やったこと\n{今日}\n\n📅明日やること\n{明日}\n\n⛔️困っていること\n{困りごと}` |
| `today` | 今日だけ | `✅今日\n{今日}` |
| `plain` | 見出し無し | `{今日}` |

差し込み (箇条は1行ずつ `- ` で始める。無ければ `- 特になし`):

| 差し込み | 中身 |
|---|---|
| `{今日}` | 今日片づけたもの (`myToday_` と同じ。反映は「確認依頼 #N 題 を正式版に反映」) |
| `{明日}` | 自分が担当の未完了で、期限か開始日が明日以前のもの (期限の早い順、10件まで) |
| `{困りごと}` | 自分が出した未解決の障害物。スクラムがオフなら `- 特になし` |
| `{日付}` | `10/14 (火)` |
| `{名前}` | 自分の表示名 (`memberNames`) |

- 知らない `{…}` はそのまま残す (消すと書いたものが黙って消える)
- 選んだ形 (`REPORT_KIND:<email>`) と自分の形 (`REPORT_CUSTOM:<email>`) を UserProperties に覚える。
  鍵にアドレスを入れる (疑似GASの UserProperties は人で分かれないため。ゲームと同じ)
- 自分の形は **2000字まで**。超えたら断る
- 自分の形を直す欄 (`openInlineForm`) では、いまの中身を当てはめた見本を見ながら直せる
- 当てはめは画面の純粋関数 `reportFill(template, parts)` で行う。中身 (`parts`) はホームを
  開いたときに取っておく (押してから取りに行くと、ブラウザによっては書き込みを断られる)

## 3. サーバ

新しいファイル `src/core/Home.gs`。アドレスを受ける関数は末尾 `_`。

| 関数 | 返すもの |
|---|---|
| `homeActivity_(email, now)` | `{weeks: [[{day, me, team}...7]...53], meTotal}`。1回の読みで自分とチームを数える |
| `homeMyTurn_(email, now)` | `{reviews: [...], returned: [...], due: [...]}` (各5件まで + 総数) |
| `homeRecent_(now)` | `[{kind, number?, fileId?, title, at}]` 10件。名前を持たない |
| `reportParts_(email, now)` | `{today: [...], tomorrow: [...], troubles: [...], date, name}` |
| `REPORT_TEMPLATES()` | ひな形の一覧 |

API (`src/Main.gs`。開いている本人のアドレスだけを渡す。`plain*` だけを通す):

| API | 中身 |
|---|---|
| `apiHomeActivity()` | `homeActivity_`。表は1回ずつ読む |
| `apiHomeSummary()` | `{myTurn, recent}` |
| `apiReportParts()` | `{parts, templates, kind, custom}` |
| `apiSetReportKind(kind)` | 知らない key は断る |
| `apiSetReportCustom(text)` | 2000字を超えたら断る |

## 4. 失敗したとき

- ホームの各区画は並べて呼び、**1つが取れなくてもほかは出す**
- あなたの番・草・最近の動きは `failInto` でその場所に「出せませんでした」を残す
  (帯は数秒で消えるので後から開いた人に伝わらない)。日報の中身が取れないときは
  今の形 (`✅今日` と箇条) で写す
- 返事が届いたときにホームを開いていなければ描かない (前の返事で上書きしない)
