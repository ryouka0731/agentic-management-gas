## 1. 設定の一覧 (#18。ほかの2つの土台)

### 一覧は1か所に置く
`src/core/Prefs.gs` に `PREFS_SCHEMA()` を置き、変えられる項目を列挙する。**これが唯一の定義である。**
画面は `apiPrefs()` で一覧と今の値を受け取り、それをもとに欄を組む。画面に写すと、足したときに「選べるのに
保存できない」項目が出る (`ISSUE_PRIORITIES` と同じ考え方)。

1項目の形:

```
{ key, scope: 'team'|'me', type: 'int'|'bool'|'enum'|'steps', label, help,
  min?, max?, options?: [{value,label}], def }
```

- `team` はチームの設定で、管理者 (`repoIsAdmin_`) だけが変えられる。スクリプトプロパティ `PREF:<key>` に置く
- `me` は自分の設定で、本人だけが変えられる。スクリプトプロパティ `MYPREF:<lowercase email>` に JSON で置く
  - **UserProperties には置かない。** 通知は送る側の権限で走り、キューは持ち主の権限で走る。
    どちらも受け取る人の UserProperties を読めない (`KIT_PRINT:` と同じ事情)
- 読むのは `prefGet_(key, email?)` だけにする。値が無い・読めない・範囲の外なら `def` を返す
  (**未設定のときは今の動きのまま**)
- 書くのは `apiPrefSet(key, value)` だけにする。`prefValid_` で型と範囲を検査し、通らなければ投げる。
  `team` の項目を管理者でない人が書こうとしたら断る
- 設定を変えても変更の履歴 (`change_log`) には残さない

### 項目

**チームの設定 (管理者が変える)**

| key | 型 | 既定 | 範囲 | 効く先 |
|---|---|---|---|---|
| `advice.<rule>.on` | bool | true | | 改善のヒントの規則ごと (reviews / overdue / wip / estimate / repeat / questions) |
| `advice.<rule>.min` | int | 今の値 | 1〜50 | 出す件数の下限 (min を持つ規則だけ) |
| `advice.<rule>.days` | int | 今の値 | 1〜90 | 日数 (days を持つ規則だけ) |
| `advice.wip.limit` | int | 3 | 1〜20 | 同時に進めてよい数 |
| `stale.steps` | steps | [7,14,30] | 1〜180 の昇順3つ | 「動きなし」の段階 |
| `home.dueDays` | int | 3 | 1〜14 | 「期限が近い」とみなす日数 |
| `usage.enabled` | bool | true | | 使われ方を記録するか |
| `usage.keepDays` | int | 180 | 90〜365 | 使われ方を残す日数 (画面は90日まで見るので90未満にしない) |
| `report.defaultKind` | enum | three | `REPORT_TEMPLATES()` のキー | 自分の形を選んでいない人の日報の形 |

- **`ADVICE_RULES()` は既定値の定義として残す。** 上書きを重ねたものは `adviceRulesEffective_()` が返し、
  `homeAdvice_` はそちらを読む。変えられる数の名前は規則ごとに `tunable: ['min','days']` として
  `ADVICE_RULES()` に書く (書いていない数は設定の一覧に出ない)
- `STALE_STEPS()` は画面と両方にある。サーバの値を `apiPrefs` の返事 (`effective.staleSteps`) で画面へ渡し、
  画面は `stalenessOf(..., steps)` に渡す。取れなかったときは今の `STALE_STEPS()` を使う
- チームの月の目標 (`apiSetTeamGoal`) は、設定の画面からも変えられるようにする (保存先は今と同じ)

**自分の設定 (本人が変える)**

| key | 型 | 既定 | 効く先 |
|---|---|---|---|
| `start.tab` | enum | home | 開いたときに最初に出す画面。選べるのは左の行き先のうち、スクラムがオフなら出ないものを除いたもの |
| `home.cards` | 各 bool | 全部 true | ホームのカード: あなたの番 / 改善のヒント / 草 / ポイント / 最近の動き / チームの前進 |
| `notify.<kind>` | bool | true | 通知メールを種類ごとに受け取るか (下) |
| `usage.self` | bool | true | 自分の使われ方を記録するか |

- 通知の種類 (`NOTIFY_KINDS()`):
  - `review`: 確認を頼まれた・確認依頼が出た
  - `result`: 反映した・取り下げた
  - `inquiry`: 報告とその返事
  - `mention`: 名指しされた
  - `comment`: やることのやりとり
  - **全部止められる** (利用者の判断)。止めた人には設定の画面で「確認を頼まれても知らせが届きません」と断りを出す
- `notify(to, subject, body, kind)` に kind を足し、宛先の人ごとに `prefGet_('notify.'+kind, email)` を見て、
  止めた人を宛先から外す。kind が無い呼び方は今までどおり送る
- `usageRecord` は、`usage.enabled` が false のとき、または記録する人の `usage.self` が false のとき、何もしない。
  画面からの送信も止める (`apiPrefs` の値を見て `usageCount` を空振りさせる)
- `usage.keepDays` は `USAGE_KEEP_DAYS()` を置き換えず、`usageKeepDays_()` が設定を読む
- `start.tab` は起動時に、`?doc=` のリンクで開いた場合を除いて使う。端末の localStorage には置かない
  (どの端末でも揃えるため)

### 画面
- 「設定」を2つの区切りに分ける: **自分の設定** (誰でも) と **チームの設定** (管理者には欄、そうでなければ今の値を
  読むだけ)。今あるスクラム・ポイント・キューの状態はチームの設定に入れる
- 欄は一覧から組む。bool はトグル (既存の `makeSwitch` などの形)、int は数の欄 (範囲を添える)、enum は選択、
  steps は3つの数の欄にする
- 保存は欄ごとに `call('apiPrefSet', ...)` で行う。失敗したら `failEnable` / `failSnack` で元に戻す。
  「既定に戻す」で項目を消す (`apiPrefSet(key, null)`)

## 2. 使われ方 (#19)

- `usageSummary` の返事に次を足す:
  - `prev`: 同じ長さで直前の期間の `{ total, byTarget }`
  - `byWeekday`: 月から日まで7つの数。日付から作り、時刻は使わない
- 画面:
  - 4枚のカードの「数えた回数」に、前の期間との増減 (±% と矢印の字) を添える。前の期間が0なら「前の期間は記録なし」
  - 2つの順位表に、前の期間との増減を小さく添える
  - **「この期間に開かれなかった画面」**: 左の行き先のうち、`view` で一度も数えられなかったものを並べる。
    行き先の一覧は画面が持っている。スクラムがオフで出ない画面は除く
  - **曜日ごと**: 7本の棒
  - **CSV で保存**: 今見ている範囲 (期間と対象) の場所ごと・日ごとの数を CSV にする。`a[download]` で保存を
    試し、Apps Script の枠の中で断られたときは、字をそのまま見せてコピーできる形 (`makeCopyRow` の形) にする。
    人の列は、今見られる範囲の人だけにする
- 人に関わる数は今と同じ (`memberVisibleTo`)。新しい数のうち人を含むのは CSV の人の列だけで、同じ範囲に絞る
- `Main.gs` の `apiUsageRecord` 付近のコメント「誰が押したかは残さない」を、実装に合わせて直す
  (人ごとの列は残す。見られるのは本人と部下だけ。順番と時刻は残さない)
- 「使い方」の節を開いた回数も数える (下の 3)。場所の名前は `guide-<id>`。`usageLabel` が節の見出しに直す

## 3. 使い方 (#20)

- `GUIDE` の各節に、英数の `id` と、任意の `admin: true` を持たせる。`figures` のキーは今と同じ見出しのままにする
  (見出しと一字一句同じであることは今のテストが見ている)
- **絞り込み**: 本文の上に `#guide-filter` を置く。打った字を見出しと行に含む節だけを出す (大小・全角半角は
  そろえて比べる)。目次も同じく絞る。0件なら「見つかりません」と出す
- **探す (Ctrl+K)**: 手元の `searchFilter` で絞る一覧に、使い方の節の見出しを「使い方」の種類として足す。
  選ぶと使い方の画面を開き、その節へ送る (`openGuideAt(id)`)
- **画面ごとの「?」**: 主な画面の見出しに小さな「?」ボタン (`.guide-link`、`data-guide="<id>"`) を置き、
  その節を開く。置く画面は、ホーム・文書・やること・確認依頼・工程表・使われ方・設定
- **管理者向けの節**: `admin: true` の節の見出しの横に `makePill('管理者', ...)` を付ける。隠しはしない
  (管理者でない人も、誰に頼めばよいかが分かる)
- **節を足す** (どれも図を付ける。図は今の `makeDiagram` で描き、枠外と重なりの検査に通す):
  - `home`: ホームの見方 (あなたの番 / 改善のヒント / 草 / ポイントと称号 / 最近の動き)
  - `view`: 文書の全画面と工程表の操作 (全画面・リンクのコピー・名前の幅・日週月・今日へ送る)
  - `usage`: 使われ方の見方 (何を数え、何を数えないか。誰の分が見えるか。止め方)
  - `settings`: 設定でできること (自分の設定とチームの設定。通知の止め方)
- 節が表示されたとき (目次から送った・絞り込みで1件になった・「?」で開いた) に `usageCount('view',
  'guide-<id>')` を数える。スクロールで通り過ぎたものは数えない (数が意味を持たなくなる)

## 判断 (戻ったら見直してほしいもの)

- **自分の設定もスクリプトプロパティに置いた。** 通知とキューが受け取る人の UserProperties を読めないため。
  欠点として、スクリプトの持ち主はエディタで他人の設定 (止めた通知の種類・最初の画面) を見られる。
  同じことは既に `KIT_PRINT:` で起きている
- **通知は全部止められる** (利用者の判断)。確認を頼まれた知らせを止めた人には、設定の画面で断りを出す
- **使われ方の記録をチームで止められるようにした。** 既定はオン。保持日数は90日を下限にした
  (画面で90日を選べるため)
- **優先度・報告の種類・札の色は設定にしなかった。** 台帳に書いた値が読めなくなる
- **曜日はあるが、時刻はない。** 時刻は最初から残さないと決めてある
- **「使い方」は管理者向けの節も隠さない。** 隠すと、誰に頼めばよいかが分からなくなる
