# 知らせの設計 (やること #108 / GitHub #131)

番頭の知らせを「使いたくなる言い方」に揃え、画面を閉じているときにも届く道を整理する。
PWA (ホーム画面に追加した番頭からの通知) は GAS の制約でできないので、代わりに何で届けるかを決める。

## 1. いま知らせが出る場所

| 場所 | 仕組み | 届くとき | 止め方 |
|---|---|---|---|
| 画面の帯と「知らせ」のベル | `noticeAdd` → 台帳 `notifications` → `apiNotifications` (1分ごと) | 画面を開いているあいだ | 止められない (本人あてだけ) |
| デスクトップ通知 | ベルの中の「デスクトップに出す」→ `window.Notification` (`popDesktop`) | **タブを開いているあいだだけ** (裏のタブでも出る) | ブラウザの許可 |
| メール | `notify(to, subject, body, kind)` → Gmail | いつでも | 設定「通知メール」の種類ごと (`NOTIFY_KINDS`) |
| あなたの番 (ホーム) | `homeMine` | 画面を開いたとき | — |
| 推しの一言 | `OSHI_LINES` の場面 (`done` / `merge` / `ask` …) | 操作した直後・ひょっこり (`oshiPeekPick` が未読の数を見る) | `oshi.on` |
| VS Code 拡張 | `homeMine` を 15 分ごと・今日の予定 (`calendarToday`) | VS Code を開いているあいだ | 拡張の設定 |

## 2. PWA の通知はできない。代わりの道

GAS の web アプリは `script.google.com` の中の `googleusercontent.com` の枠で動く。

- **manifest も Service Worker も置けない** (HtmlService は HTML しか返せず、別の origin から script を読めない)。
  ホーム画面に追加しても普通のブックマークで、Push API は使えない
- **枠の中からの通知の許可は、ブラウザによっては求められない** (Chrome は別の origin の枠からの `Notification.requestPermission` を
  断る)。いまの `desktopState()` が `unavailable` / `denied` を返す理由はこれ。使える環境では、タブを開いているあいだだけ出る

なので「画面を閉じていても届く」道は次の 3 つに絞る。**新しい外部のサービスは使わない** (UrlFetchApp 禁止。Chat の webhook も使わない)。

| 道 | 届く先 | 使う仕組み | 状態 |
|---|---|---|---|
| メール | どこでも | Gmail (既存) | あり。言い方を揃える (§3) |
| Google カレンダーの通知 | スマホのカレンダーアプリ・PC のカレンダー | 番頭が入れた予定に `addPopupReminder` (標準サービス) | **足す**。設定 `calendar.remind` (切 / 5 / 10 / 30 分前。既定は切) |
| VS Code 拡張 | 開発者の手元 | `homeMine` の返事に未読の知らせを同梱 | **足す**。命令の数は増やさない (1日の予算 `docs/dev/command-queue.md`) |

やらないこと: Google Chat (webhook = 外部 API)・Google Tasks の期限通知 (Tasks 連携はオンの人だけで、やることの写しの持ち方が別の話)・
独自の Push サーバ (外部エンドポイント)。

## 3. 言い方の決まり

知らせは「何が起きたか」ではなく「**あなたに何が来たか・次に何をすればいいか**」で書く。

1. **責めない。** 「期限切れ」「滞っている」「未対応」を見出しにしない。期日の話は「◯日までのものが 2 件あります」の形
2. **次の一歩を 1 行添える。** メールの本文の最後は必ず「次にすること」の 1 行 (例: 「確認依頼」から中身を見て、承認か差し戻しを押してください)。
   画面の知らせは開く先 (`link`) があるので本文に書かない
3. **件名の形は変えない。** `[SoftBanto] 何の #番号 どうなったか` (`notifySubject_`)。受信側の振り分けが見ている。「どうなったか」だけ言い換える
4. **推しの一言は本人の画面にだけ。** メールには入れない (推しの名前や口調が社内のメールに残る。`docs/dev/permissions.md` の
   「知らせ・メール・使われ方にも出さない」)。画面では新しい知らせが届いたとき、推しが場面 `notice` の一言を言う
5. **Git の言葉を出さない** (`test/naming.test.js`)。「やりとり」「確認依頼」「反映」
6. **数は 1 行に 1 つ。** 「3 件増えました」は書く。「増えた 3 件のうち 2 件が期限切れで 1 件が…」は書かない

### 言い換えの例

| 前 | 後 |
|---|---|
| 確認依頼 #12 の確認を頼まれました / 「確認依頼」から中身を見てください | 確認依頼 #12 があなたを待っています / 次にすること: 「確認依頼」で中身を見て、承認か差し戻しを押してください |
| やること #5 に書き込みがありました | やること #5 に返事が来ました / 次にすること: 「やること」#5 を開いて続きを書いてください |
| 確認依頼 #12 は取り下げられました | 確認依頼 #12 は要らなくなりました (改訂版は残っています) / 次にすること: ありません |

## 4. 種類と頻度

`NOTIFY_KINDS` (メールの止め方の単位) は今のまま 6 つ: review / result / inquiry / mention / comment / goal。

| kind | 画面の知らせ (`noticeAdd` の kind) | 回数の目安 |
|---|---|---|
| review | review (頼まれた・取り下げ) | 確認依頼 1 件につき 1〜2 |
| result | (画面には出さない。出した本人は見れば分かる) | 反映・取り下げ 1 件につき 1 |
| inquiry | reply | 報告 1 件につき返事の数 |
| mention | mention | 名指し 1 回につき 1 |
| comment | reply | やりとり 1 回につき 1 (関わった人全員) |
| goal | goal | 承認・差し戻し・評価 1 回につき 1 |

**足したい種類 (別のやること):** 「担当になった」(ほかの人が自分を担当に入れたとき。kind `assigned`)。いまは知らせが無く、
あなたの番に出るまで気づけない。

## 5. 画面を開いているときの出し方

- ベルの数と帯 (既存)。帯は新しい知らせの 1 件目の見出しだけ
- **タブの名前に未読の数** (`(2) SoftBanto`)。裏のタブでも気づける。集中のしかたの残り時間と重ならないよう、元の名前は 1 か所
  (`app.js` の `titleBase`) で持つ
- 推しが場面 `notice` の一言を言う (11 の口調ぶん)。推しがオフの人には出ない
- デスクトップ通知 (既存。使える環境だけ)

## 6. 作る順

1. 言い方 (`Notifier.gs` の全部の知らせ) + タブの名前の数 + 推しの `notice` + `docs/dev/notifications.md`
2. VS Code 拡張に未読の知らせ (`homeMine` の返事に `notices` を足す)
3. カレンダーの通知 (`calendar.remind`)
4. (別のやること) 担当になった知らせ

## 確かめていないこと

- 本番のメールの見え方 (Gmail の一覧で「次にすること」が切れないか)
- スマホの Google カレンダーで popup の通知が実際に鳴るか (アプリの通知の設定に依る)
- VS Code 拡張の知らせの出る頻度が多すぎないか (15 分ごと)
