# 横断検索 (ヘッダーのサーチバー) 設計

2026-10-14。利用者の依頼:「横断的に検索できるサーチバーをヘッダーに設けたい」。

## 1. 決めたこと (利用者に確かめた)

| 問い | 決めたこと |
|---|---|
| 何を探すか | **題名と名前と番号だけ** (本文・やりとり・文書の中身は探さない) |
| 見せ方 | **打つそばから欄の下に候補を出す** (結果の画面は作らない) |
| 作り方 | **題名の一覧を1回取り、手元で絞る** (打つたびにサーバへ行かない) |

## 2. 画面

### 2.1 置き場所と入口

- ヘッダーの右側、知らせ (`#bell-btn`) の左に検索欄 `#search-input` (`type="search"`、
  placeholder「探す (Ctrl+K)」。Mac では「⌘K」と出す)
- **狭い画面 (767px 以下) では虫めがねのボタン** `#search-open` にし、押すとヘッダーの上に
  画面幅いっぱいの欄を開く (Esc・外側を押す・閉じるボタンで閉じる)
- **Ctrl+K / ⌘K でどの画面からでも欄へ移る** (入力欄の中でも効く。ブラウザの既定の動きは止める)。
  `/` は今までどおりやることの絞り込み欄 (変えない)

### 2.2 候補

- 欄の下に候補の一覧 `#search-results` (`role="listbox"`)。欄は `role="combobox"`・
  `aria-expanded`・`aria-controls`・`aria-activedescendant`
- 種類ごとに見出し (文書 / やること / 確認依頼 / 改訂中の版 / 報告 / 障害物) を付け、
  **種類ごとに5件まで・全部で20件まで**
- 1行: 題名 (合った部分を `<mark>` で囲む。字は textContent で入れる)・番号 (`#12`)・状態の札
  (**それぞれの一覧と同じ言葉**。やること: 対応中 / 完了 / 置き場、確認依頼: 確認待ち / 承認済み / 反映済み / 取り下げ
  (一覧の `stateLabel` をそのまま使う)、報告: 未解決 / 解決、障害物: 未解決 / 解決済み)
- ↑↓ で選び (端で止まる)、Enter で開く、Esc で閉じて欄を空にしない、Tab で閉じる
- 何も打っていないときは出さない。合うものが無ければ「見つかりませんでした」
- 一覧が取れないときは、候補の場所に「探せませんでした: 理由」を出す (帯ではなくその場)

### 2.3 開くと

| 種類 | 開き方 |
|---|---|
| 文書 | 正式版の本文を開く (`openDoc`。文書の一覧がまだなら取ってから) |
| やること | 右のパネルで開く (`openIssueByNumber`)。**捨てたものは「捨てたもの」の置き場を開き、その行を指す** (`apiIssueList` は置き場を返さないため) |
| 確認依頼 | 確認依頼の画面でその依頼を開く (`switchTab('pulls', { pr: n })`) |
| 改訂中の版 | 改訂中の版の画面へ |
| 報告 | 要望・不具合の画面でその報告を開く (無ければ画面へ移るだけ)。報告の絞り込みの字は消し、済んだ報告なら「未解決だけ」を外す (残すと別の報告が開く) |
| 障害物 | 障害物の画面へ |

開いたら候補を閉じ、欄の字は消す。

### 2.4 合わせ方 (画面の純粋関数)

- 比べる前に、両方を **NFKC で正規化 → 小文字 → カタカナをひらがなへ** そろえる
  (全角英数・半角カナ・大文字の違いを吸収する)
- 空白で区切った語は**すべて含む**ものだけ (AND)
- 並び (高い順):
  1. 番号がぴったり (`#12` / `12` / `＃１２`)
  2. 題名が語で始まる
  3. 題名の途中に語がある
  4. 同じ段では、置き場でないもの → 置き場、状態の順 (やること: 対応中 → 完了、確認依頼: 確認待ち・承認済み →
     反映済み → 取り下げ、報告: 未解決 → 解決、障害物: 未解決 → 解決済み)、そのあと新しい番号から
- 置き場のやることと取り下げた依頼は出すが、同じ段の最後に回す

## 3. サーバ

`src/core/Search.gs` (新規) の `searchIndex_()` と、`src/Main.gs` の `apiSearchIndex()`。

返す形 (1行ずつ。`plain*` だけを通す):

```
{ kind: 'doc'|'issue'|'pull'|'branch'|'inquiry'|'impediment',
  number: number (doc/branch は 0), key: string (doc は fileId、branch は名前),
  title: string, state: string, archived: boolean }
```

| 種類 | 元 | 入れるもの |
|---|---|---|
| doc | `filesVisibleInWiki()` | 正式版のものだけ (`branchOfPath_(path) === 'main'`)。title = path |
| issue | `issues` | 全部。archived = `archivedAt` があるか |
| pull | `pulls` | 全部 |
| branch | `branches` | `state === 'open'` で main 以外 |
| inquiry | `inquiries` | 全部。title = `title` 欄、空なら本文の1行目 (`inquiryTitleOf_`) |
| impediment | `impediments` | **スクラムがオンのときだけ** |

- 表は1回ずつ読む。人の名前・アドレス (author / assignee / by / reportedBy) は**返さない**
- 誰でも一覧で見られるものだけを返す (題名はそれぞれの一覧で既に全員に見えている)

画面は、欄へ初めて移ったとき、または前に取ってから **60秒** 以上たっていれば取り直す。
**この画面で一覧に出るものを動かしたとき** (作る・題名を直す・閉じる・戻す・捨てる・反映する・取り下げる・
解決する) は、`call()` が成功した呼び出しの名前で判断して (`searchIndexChangedBy`) 古いことにし、
次に欄へ入ったとき取り直す。呼ぶ場所ごとには書かない (書き忘れた操作だけが古いまま残る)。
探して置き場へ移ったときは、やることの見え方 (`issueView`) を覚えない。
取っている途中に打った字は、届いてから絞る。返事が届いたとき欄が閉じていれば候補は出さない
(一覧だけ覚える)。**返事で画面を切り替えない。**

  名前とアドレスが入らない / 報告の題名が空なら本文の1行目
- `test/phase4-edit.test.js` の「画面に渡せる形か」に `apiSearchIndex`
- `test/component.test.js`:
  - 打つと種類ごとに候補が出る / 5件・20件まで / `#12` が一番上 / カタカナとひらがな・全角半角で合う /
    空白区切りは AND
  - ↑↓・Enter・Esc / Enter で各種類が開く / Ctrl+K と ⌘K で欄へ移る / 合わなければ「見つかりませんでした」
  - 取れないときはその場に知らせる / 返事が遅れても画面を切り替えない / 60秒以内は取り直さない
  - 狭い画面のボタンで欄が開き Esc で閉じる / 外側を押すと閉じる

  - 一覧の見出しを押しても閉じない / やることを作ったら次に欄へ入ったとき取り直す
- 純粋関数 (正規化・合わせ・並び) は `test/ui-source.js` で切り出して試す
- `test/dom.js` の `DEFAULTS` に `apiSearchIndex` を1回だけ

## 5. やらないこと

- 本文・やりとり・文書の中身の検索
- 人 (担当者・名前) の検索
- 検索結果の画面・検索の履歴
- コマンドパレット (行き先や操作への飛び先)
