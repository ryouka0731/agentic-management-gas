# エージェンティックスクラムを取り入れる

`ai-scrum-gas` の機能を、この道具に取り入れる。**画面はこの道具の作りを優先**し、
**エージェンティックスクラムは既定でオフ**にする。使う人だけが設定画面でオンにする。

## 2つの作りの違いと、取り入れ方

| | ai-scrum-gas | この道具 |
|---|---|---|
| 本体 | Drive の `scrum/` にある CSV と Markdown | 台帳 (スプレッドシート) |
| 手元の Claude | `scrum/` を直に読み書き | コマンドキューの命令 |
| PBI | `product_backlog.csv` | やること (`issues`) |

- **台帳に載るもの** (人が画面で見て操作するもの) は台帳に置き、手元からは命令で触る
  - PBI はやることに「スプリント・ポイント・受入基準」の列を末尾に足して表す
  - スプリント (`sprints`)・障害物 (`impediments`)・障害物のやりとり
    (`impediment_comments`)・変更の履歴 (`change_log`) の表を足す
- **文章の成果物** (スプリントバックログの説明、デイリー・レビュー・振り返りの記録、
  依頼書) は、これまでどおり手元の `scrum/` に書く。台帳に入れると人が読む場所が増える
- バーンダウン・ベロシティ・ロードマップは**台帳から数える**。ai-scrum-gas では
  `velocity.csv` や `sprint_backlog.md` に手で書いていた数を、やることのポイントと
  完了日から求める。手で書いた数は必ずずれる

## 既定はオフ

- スクリプトプロパティ `SCRUM_ENABLED` が `'true'` のときだけオン
- 切り替えられるのは持ち主だけ (設定画面)。オフのあいだはスクラムの API が断り、
  画面にはスクラムの行き先も欄も出さない
- 手元の道具は `node agent.mjs scrum` で状態を見られる。初回の `setup` と AGENTS.md に、
  使うなら設定画面でオンにするよう案内を出す

## 段階

1. 切り替えと設定画面 (`Settings.gs` / 「設定」の行き先)
2. 台帳の列と表、スプリント・障害物・履歴の本体 (`Scrum.gs`)
3. バーンダウン・ベロシティ・ロードマップ・要約・用語の説明 (`ScrumView.js`)
4. 画面: 「スプリント」「障害物」の行き先、やることの欄、履歴
5. 手元の道具: 命令・同梱するスキルとエージェント・案内

## 取り入れないもの

- 共有スプレッドシートへの同期 (台帳がもともとスプレッドシートなので要らない)
- `publish.js` による配布 (手元の道具の zip が代わりを務める)
- スクラムと関係の無いスキル (セキュリティ監査・playwright など)
