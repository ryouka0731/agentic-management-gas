# 使う気・仕事の意欲を生むための施策 (文献にもとづく)

利用者から「このアプリの利用や仕事をするモチベーションを生むために必要なことを論文
リサーチした上で、ゲーミフィケーションなど具体的な施策を」と頼まれた。文献を調べ、
**点数・順位・監視に頼らず、前進が見える・自分の上達が分かる・チームでつながる**に
絞ることにした。

## 文献の要点

| 知見 | 出典 | この道具での扱い |
|---|---|---|
| 自律・有能感・関係性が満たされるほど自律的な動機と仕事の質が上がる | Gagné & Deci 2005, *JOB* | 3つを満たす形にする |
| 内発的動機は成績を予測する (r=.21〜.45) | Cerasoli ら 2014, *Psych. Bull.* | 内発的動機を壊さない |
| 予告された報酬は内発的動機を下げる (d=−0.40) | Deci, Koestner & Ryan 1999, *Psych. Bull.* | **点数を配らない** |
| フィードバックは平均で効くが 38% で逆効果。注意が「自分の評価」へ移ると下がる | Kluger & DeNisi 1996, *Psych. Bull.* | 評価ではなく仕事の前進を伝える |
| 小さな前進を日々実感できることが仕事の中の気持ちを最も良くする | Amabile & Kramer 2011 (書籍) | 終えた・反映した瞬間に前進を見せる |
| 具体的な目標と途中経過の知らせで成績が上がる | Locke & Latham 2002, *Am. Psych.* | チームの毎月の目標と進み具合 |
| 感謝されると自分に価値があると感じ、助ける行動が増える | Grant & Gino 2010, *JPSP* | 「ありがとう」(次の段階) |
| ゲーミフィケーションは概ね効くが文脈に強く左右される | Hamari ら 2014; Koivisto & Hamari 2019 | 小さく入れて測る |
| 点数・レベル・順位は量を増やすが内発的動機は変わらない | Mekler ら 2017, *CHB* | 点数・レベルは入れない |
| 職場の順位の下位は晒しと受け取られる | Jia ら 2017, CHI | **人ごとの順位は作らない** |
| 新しさの効果は約4週で薄れる | Rodrigues ら 2022; Hamari 2013 | 4〜6週ごとに見直す |
| 電子的な監視は成績を上げずにストレスを増やす。透明なほど受け入れられる | Ravid ら 2023, *Pers. Psych.* | 誰に何が見えるかを明示する |
| 使うかは「役に立つ・楽・周りの勧め・支援」で決まる | Venkatesh ら 2003, *MISQ* | はじめの5歩で楽にする |
| 習慣がつくと意図より習慣が継続利用を決める | Limayem ら 2007, *MISQ* | 前進の知らせを毎回返す |

効果量の多くは学習分野・西洋の参加者のもので、日本の事務職場にそのまま当てはまるかは
確かめられていない。だから入れたら測る。

## 入れたもの (第1段階)

1. **前進の知らせ** — やることを完了にしたとき・正式版に反映したときに「今週チームで◯件目」を
   添える。今月の目標に届いたらそれも添える (進歩の原理・有能感)
2. **チームの毎月の目標** — 管理者がチームに1つだけ決め、ホームに進み具合を出す。人には割り
   振らない (目標設定・関係性)
3. **はじめの5歩** — 改訂版を作る → 記録 → 確認を依頼 → ほかの人の依頼を確かめる → 反映。
   本人にだけ見え、次の一歩だけ入口を出す。全部できたら消える。閉じられる (楽さ・有能感)
4. **自分で止められる** — 自分まわりの「前進の知らせを出す」で、知らせもホームのカードも止める
   (自律性・同意)。**この端末のこのブラウザにだけ覚える** (別の端末やサイトのデータを消したあとは
   出る)。利用者ごとに覚えるのは次の段階
5. **見える範囲の明示** — 工数の集計に「誰に何が見えるか」を書く (透明性)

## やらないこと

- 上司に見える個人ランキング / 点数・レベル / 予告した報酬

**既存の例外 (上長に確かめる):** 「使われ方」の画面は、上長に部下の人ごとの利用回数を名前と
棒で並べている (以前、本人と部下にだけ見せると決めた)。文献に照らすと監視・順位と受け取られ
うるので、人ごとの棒をやめてチームの合計だけにするかを上長に確かめる。決まるまでは今のまま。
- 利用回数を人事評価に結び付けること
- 途切れたことを責める知らせ

## 次の段階

- 確認依頼の承認・やりとりへの「ありがとう」(回数の一覧は作らない。上司向けの集計に入れない)
- 週ごとのふりかえりの要約 (チーム宛て。前進・ありがとう・課題)
- 任意で、途切れても許す週単位の連続記録 (初期は切っておく)

## 測り方

いまの記録で数えられるもの:

- `apiProgress` の週・月ごとのチームの件数 (終えたやること・正式版にした文書) の推移
- 「使われ方」のチーム合計で、画面ごとの利用回数の推移 (入れる前の4週と、入れたあとの4週)

いまは数えられないもの (次の段階で、人を追わない形で数える仕組みを足す):

- 前進の知らせを止めた割合 (止める設定はブラウザにしか残らない)
- 知らせを出したあと7日以内にまた使った人の割合、最初の反映までの日数
