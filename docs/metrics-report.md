## 測り方を直した

1. **画面の JS がカバレッジに数えられていなかった。** `test/dom.js` が画面の JS を `new Function` で
   走らせていて、名前の無いコードとして扱われ、どのファイルにも結び付かなかった。つないだものを
   `coverage-ui/app.joined.js` に書いて名前の付いたファイルとして読み、source map で元の部分ファイルへ戻す
   形にした (`test/ui-source.js` の `appSourceMap`)
2. **画面が投げた例外を、テストが見逃していた。** jsdom は聞き手や返事のハンドラの例外を console に
   出すだけで、テストは通っていた。`test/component/mount.js` で拾い、そのテストを落とすようにした。
   その時点で1件 (工数の集計の表を古い形の返事で描いていた) が見つかった
3. **測る道具を足した。** `scripts/metrics.mjs`。依存は足さず、vitest が持っている構文解析を使う。
   画面の JS は `wiki.html` の並びどおりにつないで読み、位置を元のファイルへ戻す。
   画面を包む一番外の関数 (1万6千行) は、1つの関数としては数えない

## テストで見つけて直した不具合 (13 件)

| # | どこで | 何が起きていたか |
|---|---|---|
| 1〜4 | Markdown の読み戻し | 太字と斜体を重ねた `***重要***`、装飾の端の逃がした `\*`、リンクの字の中の `](`、閉じない `**` で字が崩れたり消えたりしていた。Markdown で保存すると、触っていない段落まで崩れた |
| 5 | `apiStashMainDrift` | 時刻が Date のまま画面に返り、`null` で届いていた |
| 6 | やることの更新 | 題名を空にできた (作るときは断るのに) |
| 7 | 下書きのひな形 | 一覧を一度も開かないうちに保存すると、決まったひな形が入らず、その名前で上書きできた |
| 8 | 下書きのひな形 | ほかの人が作ったひな形を、同じ名前で上書きできた |
| 9 | 確認依頼の断り | 版の名前が括られずに出ていた (`同じ版には反映できません: main`) |
| 10 | やることの断り | 関数の名前が出ていた (`stateはissueCloseで…`) |
| 11 | 手元への頼みごと | 画面の口から `merge` を頼めた (承認したときに自動で置くので二重になる) |
| 12 | 確認依頼のやりとり | サーバの内部の印 (`[target-file:…]`) が本文として出ていた |
| 13 | 画面のテスト | 集計の表を古い形の返事で描いて落ちていたのに、テストが通っていた |

どれも、直す前の形に戻すとテストが落ちることを確かめている。

## 確かめていないこと

- **実機で走らせていない:** Docs への書き戻しを分けた形 (`writeBlocksToDoc`) と、Markdown の読み手。
  疑似の DocumentApp で呼び出しの順は固定したが、実機の `debugWriteRoundTrip()` と
  `debugMarkdownRoundTrip()` はまだ走らせていない
- **画面の見え方:** jsdom で組んでいるので、描画とレイアウトはテストでは見ていない
- **テストの時間:** 全体は 136 秒から 157 秒に延びた。機械が混んでいると、時間を測る2つのテスト
  (`kit-track` の「2秒以内」、`kit-commands`) が落ちることがある。単体では通る
