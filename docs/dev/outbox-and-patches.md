# コードの証跡と手元への頼みごと

`CLAUDE.md` から分けた。下に挙げた場所を触る前に読むこと (`CLAUDE.md` の「触る場所と、先に読むファイル」)。

## コードは git が持ち、この道具は確認だけ持つ

`src/core/PullPatch.gs` が、確認依頼に添えるコードの差分を扱う。

**この道具はコードの版管理をしない。** git にも GitHub にも無いのは「非
エンジニアが画面で読んで承認する」ところだけで、版管理は既にある。

- **patch を `files` に入れない。** `files` の1行は「管理している Drive の
  ファイル」で、改訂版・作業コピー・書き戻しの一式がその前提で組まれている。
  patch にはコピーも編集も書き戻しも無いので、混ぜると `branchAddFile` /
  `fileStatus` / `writeHtmlToFile` に「patch のときは何もしない」枝が散る
- 差分の本文は `objects/` に置く。台帳のセルには上限がある
- **差分を取るのは手元。** GAS では git のオブジェクトを読めない (loose object
  は raw deflate で、Apps Script には raw inflate が無い。packfile はさらに
  delta チェーン)。`agent.mjs patch` が `git diff` を走らせて送る
- **`pull_patches.id` は依頼をまたいだ通し番号にする。** 依頼ごとに振ると
  番号がかぶり、`dbUpdate` / `dbDelete` は id だけで行を探すため、関係のない
  依頼の証跡を書き換えたり一緒に消したりする（実際にその形で書いて捕まえた）
- **反映しても、コードは書き換わらない。** 画面の断りに必ずそう書く。書かないと
  「承認したのに入っていない」になる。文書が無い依頼ではボタンの字も
  「承認を記録する」に変える
- 文書が無くコードの証跡だけの依頼を**断らない**。断ると承認を記録する道が
  無くなり「読んで納得したのにどこにも残らない」ことになる。承認1件は必須のまま

## この道具から手元へは「取りに来てもらう」

`src/core/Outbox.gs`。**外部 API は使わないと決めてあるので、手元の Remote
Control に直に投げることはできない。** Drive の同期に乗せ、手元から取りに来る。

```
手元 --(.cmd.json)--> queue --(1分)--> この道具が実行   … これまで
この道具 --(outbox の行)--> 手元が取りに来て実行         … こちら
```

**押すのではなく取りに来る形である。** 寝ている機械は起きない。承認の取り次ぎ
のような人の時間の単位なら困らないが、時計として使ってはならない。画面にも
「送りました」とは書かない（すぐ動くと思われる）。

### 頼めることは列挙する

この表は台帳にあり、Drive を共有している人なら手で書き換えられる。**頼みごとを
自由な文字列にすると、Drive に書ける人が全員の手元マシンで好きなコマンドを
走らせられることになる。**

- 動詞は `OUTBOX_VERBS()` に列挙する。増やすときは「手元で何が起きるか」を
  書いてから増やす
- 引数は `outboxArgValid_` を通す。**通す字を並べる形にはしない。** この道具の
  ブランチ名は日本語である（「見直し」）。ASCII だけに絞ると正規の名前が弾かれ、
  承認しても手元に頼めなくなる（実際に踏んだ）。代わりに空白・制御文字・シェルの
  記号と `..` を弾く
- 決めた欄以外の引数は捨てる。通すと手元で字をつなげてコマンドにされうる
- **そのうえで `agent.mjs` は頼みごとを実行しない。** 中身を Claude に見せる
  ところまでで止め、何をするかは人と Claude が決める。`test/agentkit.test.js` の
  「この道具は頼みごとを実行しない」が `execFileSync` の数を1件（patch を作る
  ぶんだけ）に固定している

### 取った印を付けてから返す

付けないと、2つの手元が同じ頼みごとを別々に進めて、同じ差分が2回添えられる。
取ったまま24時間動かないものは `outboxReclaim` で `open` に戻す（手元が落ちたり
人が忘れたりするため。戻さないと誰も取れないまま残る）。

`id` は通し番号。依頼ごとに振ると `dbUpdate` が関係のない頼みごとを書き換える。

承認時の起票は**失敗しても反映を巻き戻さない**。通知と同じ扱いである。

画面からも頼める（`diff` / `review`）。**`merge` は手では頼ませない**。承認した
ときに自動で置かれるので、二重になる。頼めることは `apiOutboxVerbs` に出させる
（画面に写すと、動詞を足したときに「選べるのに置けない」ものが出る）。

「手元への頼みごと」の見出しは**証跡が無くても出す**。「差分を出して」は証跡を
作る前に頼むものなので、出さないと頼めない。
