# 落とし穴 (サーバ側)

`CLAUDE.md` から分けた。下に挙げた場所を触る前に読むこと (`CLAUDE.md` の「触る場所と、先に読むファイル」)。

## 落とし穴

- **Docs に空の字を入れる操作は、実機では断られる** (`Cannot insert an empty text
  element.`)。表のセルを `setText('')` で空にしてから書く作りだったため、中身の
  あるセルを持つ表は、反映でも Markdown 保存でも書き戻しが毎回失敗していた。セルの
  字は `appendTable` で入れ、装飾は位置で当てる。`test/htmlwriter.test.js` の疑似
  DocumentApp がこれを断る (実機の debugWriteRoundTrip で見つかった)
- **台帳に書いた 'yyyy-MM-dd' の字は Date で返ってくる。** Sheets が日付として
  持つためで、疑似GASは字のまま返すのでテストでは現れない。字のまま比べると
  `usage` の足し込み・間引き・集計が全部外れ、`toISOString` すると東京の0時が
  前日15時Zになる (ToDo の期限が1日前に届いた)。日を読むところは Date も受ける
- **`files.path` は一意でなければならない。** 作業コピーは path で引くので、
  同じ名前の文書が2つあると改訂版が別の文書の作業コピーを掴み、**反映した
  時点で関係のない文書に変更が入る**。`repoRegisterFile` が重なりを断る
- **承認は人ごとの最後の判断だけを数える** (`prDecisions_`)。過去の承認を全部
  数えると、差し戻されたまま反映できる。差し戻しが残る間は反映しない
- **承認は、承認した時点の中身にだけ効く。** 改訂版の対象文書を記録したとき
  (`commitFile` → `prSourceChanged_`) と証跡を足し外ししたとき (`prMarkChanged_`)、
  その時点までに出た確認の番号を `pulls.staleReviewId` に覚え、それ以下の承認は
  数えない。**時刻で比べない**（同じミリ秒だと前後が決まらない）。差し戻しは
  古くしない。同じ差分の送り直しは中身が変わらないので古くしない
- **Sheets の書き戻しは変わったセルだけを書く** (`sheetWriteBlock_`)。読むのは
  表示値なので、表示値を書くと触っていないセルまで丸めた値に置き換わる
  (3.14159 → 3.14、書式で付けた先頭の0)。`clear()` もしない（表示の書式が消える）
- **3つを見比べる反映は、重なる変更をつながる限りまとめる** (`merge3`)。1つずつ
  突き合わせると、片側の1つの変更が相手の2つにまたがったとき行が消えたり戻ったり
  した。同じ位置では挿入を先に置く。`test/merge.test.js` の「ランダムな編集で
  崩れない」が性質を守っている（手で思い付く例では見つからなかった）
- **Markdown の逃がしは、読む側も同じ規則で戻す。** 逃がした `\*` を装飾と読む、
  `\|` でセルを割る、URL の `)` で切れる、の3つを踏んだ
- **CacheService の上限は1つの値につき100KB (バイト)。** 字数で区切ると日本語で
  超える。キャッシュに置けなくても文書は返す
- **疑似GASの `getLastUpdated` は変わらない限り同じ時刻を返す。** 以前は呼ぶたびに
  今を返していて、これを鍵にするキャッシュが当たったり外れたりした

- **台帳に書く字は、先頭に `'` を付けて書く** (`dbCell_`)。Sheets は appendRow /
  setValues で書いた字を人が打ち込んだのと同じに読み、'1/2' は日付、'007' は 7、
  '=' 始まりは台帳の中で数式になる（数式の差し込み）。`dbUpdate` は直さない欄も
  書き戻すので、ここを通さないと次の更新で化ける。日付として書いている欄
  (`DB_TYPED_COLUMNS`) と数そのものの字だけは解釈させる。疑似GASも既定で
  実機と同じ読み方をする（字のまま持つ形は `fake._parseLikeSheets(false)`）。
  以前は字のまま持っていたため、この類の不具合がテストに一度も現れなかった
- **期限や開始日のように時刻を持たない値は `plainDay` で渡す。** 台帳からは東京の
  0時の Date で返るので、`plainDate` で ISO にすると前日の15時Zになり、画面の
  `substring(0, 10)` で1日前に見える。編集画面にもその値が入り、保存のたびに
  1日ずつ前へずれていた
- **上書きする操作は、開いたときの指紋と比べる。** Markdown 保存
  (`apiGetMarkdown` の `baseSha`) と反映 (`apiPrPreview` の `previewSha`) がそう。
  比べないと、開いたあとの Docs での編集を消したり、見ていない食い違いの解き方で
  反映したりする。指紋を持たない呼び方（コマンドキュー）は通す

- **一覧で行ごとに `dbFindOne` / Drive を呼ばない。** 1件ごとに表を丸ごと読む
  ことになる (ボードが30枚で30回読んでいた)。先に1回読んで引く表を作る

- **`commitHistory` は親チェーン順**。timestamp だけで並べると同一ミリ秒で
  順序が不定になる（実際に踏んだ）
- **新しい GAS サービスを使ったら `appsscript.json` の `oauthScopes` に足す**。
  `GmailApp` を使ったのに足し忘れ、`notify()` の try/catch が例外を握ったまま
  通知が一度も届いていなかった
- **イテレータを回しながら Drive のファイルを移動しない**。先に対象を集める
- **フォルダを移すのは `moveTo` だけ。** `addFile` は共有ドライブで例外になる (ファイルは親を1つしか
  持てない)。以前は `addFile` と `removeFile` を両方呼ぶ形で、マイドライブでしか動かなかった。
  `test/fakegas.js` は `_markShared` した場所への `addFile` を投げる。**`removeFile` は空実装で
  `addFile` が親を移すので、マイドライブのテストだけでは片方だけの書き方が通ってしまう**
- **共有ドライブでゴミ箱へ移せるのはコンテンツ管理者から。** 人が押した操作は `driveTrash_` で
  要る役割を添えて断る。片付けのついで (古い zip など) は握って続ける

## 数え方を決めたら、数字を見せる場所すべてに書く

やることの担当者は複数入る (`issues.assignee` はカンマ区切り)。工数は
**集計のときに頭数で割って**数える。それぞれに全部を足すと、人ごとの合計を
足しても全体の合計に戻らない。

この手の「そう決めた」だけの規則は、決めた場所にしか無いと誰にも伝わらない。
割り当てる欄・集計の表・使い方の3か所に同じことを書いてある。**片方だけ
直すと食い違う。**

## 並び順を変えたら、偶然一致していないか確かめる

`issueList` は**優先度が高いものを先に、同じなら新しいものから**返す。ボードは
人が掴んで並べた `order` を持っているので、あちらは触らない。

**並び順のテストは、作る順を期待する並びの逆にする。** 同じ向きに作ると、
並べ替えを止めても「新しい順」が偶然同じ並びになり、テストが何も守らなくなる
（実際に一度そうなっていた。`test/priority.test.js` の `three()` にその断りが
書いてある）。
