# 使う人に GAS を触らせない (入れた道と出る道)

`CLAUDE.md` から分けた。下に挙げた場所を触る前に読むこと (`CLAUDE.md` の「触る場所と、先に読むファイル」)。

## 使う人に GAS を触らせない

**ファイルの id を調べてスクリプトプロパティに書かせない。** この道具を使うのは
総務・人事であって、GAS を知っている人ではない。実際に「スクリプトプロパティに
ファイル ID を渡す、が分からない」という声が来た。

文書の登録は画面から行う (`apiFoundFiles` が入れ物を覗き、`apiRegisterFiles` が
まとめて登録する)。`debugRegisterFile()` は開発時の入口として残してあるだけ。

エディタで実行させてよいのは、**最初の一人が一度だけ実行するもの**に限る
(`setupRepo` / `setupCommandQueue`)。それ以外を手順に書いたら、その時点で
設計が間違っている。

**入れた道は、出る道と対でなければならない。** 登録は画面からできるのに外す
道が無く、間違って登録したものは台帳を手で直すしかなかった。`apiUnregisterFile`
を足してある。同じ穴が確認依頼にもあった（`closed` という状態と「取り下げ」
という表示は最初からあったのに、そこへ至る道が無かった）。`prClose` を足した。

**動かしたものは、戻すときも戻す。** 確認依頼を出すとカードが「確認中」へ
動くので、取り下げでは「作業中」へ戻す。片方だけだと、誰も見ていない依頼の
カードが確認中に居座る。`test/prclose.test.js` の「カードを確認中から戻す」が
これを固定している。

**取り下げても改訂版は捨てない。** 取り下げるのは「いま反映してよいか尋ねる
こと」であって、直した中身ではない。反映済みのものは取り下げられない（書き戻し
は終わっており、取り消すには戻す記録を別に作るしかない）。

外すのは**台帳の1行だけ**で、Drive の文書も記録も消さない。だから外すのは
取り返しがつき、持ち主だけに絞っていない（間違って登録した本人が直せない
ほうが困る）。断るのは作業コピーそのものを名指しされたときと、改訂版が
残っているときだけ。未コミットは理由にしない（何も壊れないうえ、外せない
状態が増えると「どうすれば外せるのか」が分からなくなる）。

**Drive で消された文書は、一覧に出さない** (`filesVisibleInWiki`)。台帳の行と
履歴は残すので、ゴミ箱から戻せばまた出る。元の (正式版の) 文書が消えた作業
コピーも出さず、中の文書が全部見えなくなった改訂版は改訂版の一覧からも外す。
Drive はフォルダごとに1回だけ読み、見当たらないものだけ1つずつ確かめる
(`filesPresentInDrive_`)。文書ごとに問い合わせると、文書の数だけ待つ。**それでも本番で1回 1 秒かかり、
開いた直後に3回 (文書の一覧・前進の中身・ホームの要約) 走っていた** (2026-10-27)。同じ実行の中では覚え
(`dbRunMemo_`) を返し、ほかの実行とも CacheService で共有する (`FILES_PRESENT_CACHE_SEC` = 120 秒)。鍵に
files と branches の版 (`dbReadAll` のキャッシュの版) を含めるので、登録・外す・改訂版の出し入れなど台帳が変われば
すぐ新しくなる。**Drive の側だけで消した・ゴミ箱から戻したものは、120 秒まで古いまま見える。** 鍵の中で files /
branches を書いた直後 (`dbTableDirty_`) は覚えを見ない。`test/files-present-cache.test.js`。

**元の文書が消えた確認依頼は、すぐ取り下げる** (`prWithdrawOrphans`)。ゴミ箱に
入れた時点で消えたものとして扱う。開いたままだと、ゴミ箱の中の文書へ反映できて
しまう。一覧を開いたとき・反映を押したとき・1日1回の片付けで確かめ、頼まれた人
には理由を添えて知らせる。間違えて消して戻した場合は、出し直してもらう。

**ゴミ箱の印は使わない。** 文書そのものを消すと読まれる。集まりから抜く印
(`minus-circle`) を使い、帯の文でも「文書そのものは消えません」と言い切る。

パスが作業コピーかどうかは `branchSplitPath_` で判定する。
`indexOf('branches/') === 0` を散らすと、語彙が変わったときに直し漏れる。
