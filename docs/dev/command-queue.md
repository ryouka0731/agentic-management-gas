# コマンドキュー

## コマンドキューの落とし穴

(元は「落とし穴」の項目)

- **コマンドキューは「処理済みへ移す」だけでは二度実行を防げない。** 命令は手元が
  Drive の同期フォルダに置いたもので、手元に実体が残っていると同期の都合で
  `queue/` に戻ってくる。実際に「やることを1つ作ったのに、同じものが番号違いで
  複数できた」という形で現れた。`commandAlreadyRan_` で処理済みフォルダを見て
  弾き、`agent.mjs` 側も結果を受け取ったら命令を消す
- **結果を書く前に処理済みへ移す。** 逆にすると、結果を書いた直後に実行が
  打ち切られた場合 (6分の上限など) 命令が `queue/` に残り、次の起動でもう一度走る
- **キューの置き場は、ゴミ箱に入っていたら作り直す** (`queueFolderLive_`)。Apps Script は
  ゴミ箱の中のフォルダも開けるので、開けるかだけを見ると命令がゴミ箱に置かれて誰も
  拾わない。`setupCommandQueue()` もゴミ箱の中の ID を返し続けた (実機で踏んだ)
- **キューは仕掛けた人の権限で回る** (`QUEUE_RUNNER`)。共有ドライブでその人が抜けると止まり、
  他人のトリガーは見えない。`processCommandQueue` が回った時刻 (`QUEUE_LAST_RUN`) を残し、設定の
  画面が1時間より前なら引き継ぎ方を出す (持ち主 = 共有ドライブでは管理者の役割の人が `setupCommandQueue()`
  を実行する。`assertOwner_` なので投稿者などの管理者には動かない)。仕掛けた時刻 (`QUEUE_RUNNER_AT`) も
  残し、新しいほうで決める (仕掛けた直後は回った時刻が無い)。回った時刻は置き場を開けてから書く。
  確かめの入口 (`debugVerify*`) は手で回したぶんを元に戻す。人のアドレスを
  含むので `apiSettings` は管理者にだけ返す
- **置いた人 (`by`) を権限に使うのは、管理者だけの命令 (`COMMAND_ADMIN_OPS()` = `oshiProfileSet`) だけ。** ほかは誰の見え方かを
  決めるだけ。管理者だけの命令は `COMMAND_PERSONAL_OPS()` にも入れて持ち主と最後に書いた人を見比べ (`commandPersonOf_`)、
  **Drive の拡張サービスが無くて見比べられないときは決めない** (`strict`)。マイドライブでは命令ファイルの持ち主を移せるので、
  持ち主だけで決めると、管理者に持ち主を移したファイルで管理者になりすませる。断るのは `repoAssertAdmin_(what, by)`
