# 画面から呼べる関数・持ち主・管理者

`CLAUDE.md` から分けた。下に挙げた場所を触る前に読むこと (`CLAUDE.md` の「触る場所と、先に読むファイル」)。

## 画面から呼べる関数

**末尾が `_` でない関数は、すべて画面の `google.script.run` から呼べる。**
エディタで動かすつもりの関数も例外ではない。`setupRepo` は初期化済みなら断り、
`debug*` と `setupCommandQueue` は最初に `assertOwner_()` を呼ぶ。**エディタ用の
関数を足したら、同じく最初に呼ぶ。** `test/phase4-edit.test.js` の「エディタ専用の
関数は、持ち主以外には動かない」に名前を足すこと。

今は `access: MYSELF` なので害は出ない。`executeAs: ME` で共有すると、中の関数
(`dbUpdate` など) まで持ち主の権限で呼べるので、その前に組み替えが要る (`docs/manual/admin.md`)。

人に関わる数（工数・使われ方）は、本人と部下のぶんだけ見せる (`memberVisibleTo`)。
**使われ方の CSV (`apiUsageRows`) は、見られない人の行を入れない。** 名前を空にして数だけ残すと、
見られない人が1人のとき、その人の日ごと・場所ごとの記録がそのまま読める。そのため CSV を足しても画面の
合計と合わないことがあり、画面にもそう添えてある。
改訂版を捨てるのは、取り下げと同じく作った本人か持ち主だけ。

**唯一の例外が週の上位 (`apiGameTop`) である。** 利用者の判断で入れた。既定オフ・
本人が参加を選んだ人だけ・上位3位まで・週ごと・アドレスは返さない、の守りを崩すと
晒しと監視になる。上位にいない人に自分の順位を返さない (`gameMine_` は順位を持たない)。
ポイントは台帳から数えて保存しない。レベルの最高だけ UserProperties に覚える
(取り消しで下がらないように)。

確認にもポイントが付く (`gameReviewCredits_`)。**ほかの人の依頼への返事だけ・同じ依頼には1人1日1点まで**
(数稼ぎをさせない)。称号 (`gameBadges_`) は**本人にだけ**返し、台帳から数えて保存しない (取り消せば消える)。
先週のチーム (`gameTeam_`) は**合計だけ**で名前もアドレスも入れない。**終わった週 (先週・先々週) だけ**を
返す (今週の合計は動くので、読むたびの差から1人の増えた分が見える)。**週ごとに、見る人のほかに2人以上
ポイントのあった週だけ数を出し、そうでなければ null** (見る人は自分の点を引けるので、ほかに1人だとその人の
数がそのまま見える。人数を何週もまたいで数えると1週の中では1人ということがあり、同じく漏れる)。
**見る人が分からない (空) ときは丸ごと null** (全員を「ほかの人」と数えてしまう)。どれも連続日数は持たない。

**集中のしかた (`src/core/Focus.gs` / `src/api/Focus.gs`) の記録は本人にだけ。** `apiFocus*` はどれも開いている本人の
ぶんだけを扱い、ほかの人の記録の id を名指しされたら断る (`focusOwn_`)。アドレスを受ける関数は末尾 `_`。技の図鑑・
今週の数・始めるまでの時間は台帳から数えて保存せず、**連続日数は持たない**。得ていない技は名前も返さない (画面は ???)。
使われ方・工数の集計・最近の動き・探す一覧・メールには入れない。始めたことのポイントは**週の上位に参加している人だけ**
(`gamePointsBySpans_` が `gamePlayers_` で絞る)、同じやることには1人1日1回まで、**1人1日 `FOCUS_DAY_POINTS()` (2) 点まで**。
**ポイントは台帳の手 (`FOCUS_LEDGER_PROOFS()`: やりとり・直す・記録・ボード) で確かめた始めだけ。** 最初の一手は書けば
付くので、本人の「始めた」(技・数) にはするがポイントにしない。始めるボーナス・電光石火の「開いた時刻」は
`apiFocusOpen` がサーバの時計で覚えたものだけを使う (`focusTakeOpened_`。画面が送る時刻は読まない)。
`done` で終えるのはやることが完了のときだけ (`focusEnd_` が台帳で確かめる。違えば `stopped`)。確かめる範囲は
始めてから決めた長さ (+延ばした分、12時間まで) で、12時間を過ぎて置いてあるものは確かめる・延ばす・終えるで `left` にする。
`apiFocusOpen` / `apiFocusProve` / `apiFocusExtend` / `apiFocusEnd` も `apiFocusStart` と同じく自分の設定 (`focus.start`) を見る。台帳の表 `focus_sessions` は
ほかの表と同じく、台帳を直接開ける人には読める (画面から他人のぶんを返す入口は作らない)。
**仕事のスタンス診断の結果 (`src/core/WorkStyle.gs`) は本人のもの。** スクリプトプロパティ `STYLE:<小文字のアドレス>` に置き、
台帳には置かない (台帳は Drive を共有している人なら誰でも読める)。ほかの人の結果を名指しで読む入口は作らない。ほかの人に返すのは、
本人が自分の設定 `style.share` をオンにした人の**型の名前と絵だけ** (`apiWorkStyleTeam` / `workStyleShared_`)。点数・答え・日付は
入れない (上長にも返さない。`memberVisibleTo` の範囲にもしない)。結果を消したら `style.share` も既定 (見せない) に戻す
(戻さないと、診断し直したとき選んだ覚えの無いまま見える)。手元の命令 `workStyle` は置いた人のぶんだけ返し、点数は入れない (結果は手元が受け取るまでキューの置き場にあり、置き場を共有している人なら型の名前を読める。`homeMine` と同じ扱い)
(返事は入れ先に置かれ、共有している人なら読める)。
**自分へのご褒美 (`src/core/Reward.gs` / `src/api/Reward.gs`) は本人のもの。** スクリプトプロパティ `REWARD:<小文字のアドレス>` に
1人1つ置き、台帳には置かない (仕事のスタンス診断と同じ事情)。`apiReward*` はどれもアドレスを受けず、ほかの人のご褒美も交換した
記録も返さない。**たまった数は台帳から数えて保存しない** (`rewardEarned_`): ポイントとレベルがオンで週の上位に参加している人は
ポイント、ほかは本人が済ませたやること1件を1。どちらも初めて開いた時刻 (`since`) から。やること1件を1と数えるときは
`since` より後に作られたものだけ、担当なしで閉じた人の取りぶんは1日5件まで (数稼ぎにしない)。数え方 (`unit`: `game` / `done`) を
覚えておき、変わったら (`rewardSync_`) いまから数え直し、前の交換はまとめ (`archived`) にして画面で知らせる。1人ぶんは
スクリプトプロパティ1つ (9KB まで) なので、交換の記録は30件と 8000 バイトに収まるまで古いものから合計にまとめる (`rewardFit_`)。参加していない人のポイントを数えて見せる
道は作らない。覚えるのは交換した記録だけで、残りを超える交換は鍵の中で断る (たまった数を数えるのは鍵の外)。最後の交換は
サーバの時計で5分のあいだだけ取り消せる。**お金・賞品・給与・評価とは結び付けない** (画面と手引きにもそう書く)。
思いがけない当たり (js-luck) は画面の中の飾りで、ポイントを付けない (画面の乱数で台帳の数を動かさない)。

**推し (`src/api/Oshi.gs`) の入口はどれもアドレスを受けない。** 開いている本人の自分のキャラの名前・口調・せりふ・画像だけを
読み書きする (`test/oshi.test.js` の「入口はアドレスを受けない」)。画像は中身の指紋ではなく、自分のキャラの番号 (`charId`) と表情の
名前で引くので、ほかの人の画像の指紋を知っていても読めない。**`charId` は人ごとの番号**なので、ほかの人の番号を名指しても
自分の中から探すだけで、無ければ「そのキャラは見つかりません」で断る (読む道は null)。使うキャラ (`oshi.char`) に選べるのも、
最初からいるキャラと本人のキャラだけ。なつき度は **Lv = 1 + 取った実績の数** で決まり (`oshiGrowth_` → `achLevel_`)、ポイントでは
育たない。実績は消さないので段も下がらない (前の `OSHI_STAGE_MAX:` は床として読むだけで書かない。下の「実績」の `achStageFloor_`)。**ただし台帳 (`oshi` / `oshi_images`) と
`objects/` は入れ物の中にあり、Drive で共有している人は直に開ける。** 画面と手引きにもそう書いてある (隠せるとは言わない)。

キャラ作成キットの取り込み (`apiOshiCharImport`) もアドレスを受けず、開いている本人のキャラを作るか直すだけ (番号は自分の中から探す)。
頼み文 (`apiOshiCharKitPrompt` / 命令 `oshiPrompt`) は定義の字だけで、誰に返しても同じ (命令は置いた人を見ない)。
考え中のせりふ (命令 `oshiSpinner` → `oshiSpinnerLines_`) は**置いた人 (`by`) の自分の設定** (`oshi.on` / `oshi.char`) だけを見て、
その人のキャラのせりふを返す (`COMMAND_PERSONAL_OPS()`。ほかの人の自分のキャラは `oshi.char` の検査で選べないので返らない)。
自分のキャラのせりふは本人の字なので、返事は入れ先に置かれ、共有している人なら読める (`homeMine` と同じ扱い)。

**推しのプロフィール (Lv で少しずつ分かる) とクリア。** どこまで見せるかはサーバが決める (`oshiProfileReveal`。Lv = `achLevel_`、
クリア = 今の `ACHIEVEMENTS()` を全部取った `oshiClearedOf_`)。届いていない項目は名前も中身も返さず (Lv だけ)、クリアのお祝いの
言葉と動画の id は**クリアするまで返さない** (`apiOshiGet` の `clear` は null)。**最初からいるキャラのプロフィールはリポジトリに
置かない** (実在の人に寄せた中身になりうるため。スクリプトプロパティ `OSHI_PROFILE:<key>` にだけ置き、1つ 9KB を超えるときは
頭に `{"parts": N, "v": 版}` を置いて続きを `OSHI_PROFILE:<key>:<版>:0`〜 に分ける。**新しい版の続きを置く → 頭を替える → 前の版の
続きを消す、の順** (前を先に消すと、途中で止まったときにプロフィールが消える)。版は置き直すたびに変わる数 (時刻) で、頭を替えたあと
いまの版でない続きを全部消す (途中で止まった版も残さない)。読むときは続きを1つずつ問い合わせず、`getProperties()` の1回で読み、
版ごとに CacheService `OSHI_PROFILE_C:` に6時間覚える。版の無い `{"parts": N}` と `:0`〜 も読む)。
クリアは一度届いたら覚える (`OSHI_CLEARED:<小文字のアドレス>` = 届いた日。`oshiCleared_`)。あとから実績を足しても、クリアを取り上げない。
**クリアは「この環境で取れる実績 + 取った実績」を全部取ったとき** (`oshiClearedOf_(have, off)`)。取れない実績と理由を決めるのは
`achUnavailable_` (AchievementsStore.gs) だけで、実績の頁の数 (`total` / `got` / groups)・「あと◯件で…」・「クリアで分かる」の Lv
(`reveal.maxLevel`) も同じものを使う。**外すのはチームと環境の理由だけ** (1人・チームの `goals.enabled` / `usage.enabled`・共有カレンダーが無い)。
自分の設定 (`usage.self` / `oshi.on` / `focus.start` / `calendar.plan`) で止めているものは外さず、`achPersonalTips_` が手がかりを出すだけ
(自分で切るだけでクリアに届き、クリアは消えないので取り返せない)。1人かどうか (`achSolo_`) は、Drive (共有ドライブなら `driveMembers_` の admins、
マイドライブなら入れ物の持ち主と `getEditors`) が1人と言い、**しかも台帳 (members / pulls の作った人と確認を頼まれた人 (reviewers) /
reviews / issue_comments / issues の担当 / usage) に本人のほかのアドレスが無いときだけ** 1人。**グループ・ドメイン・リンクでの共有があれば
何人いるか分からないので `unknown`** (共有ドライブは役割に type が user 以外のもの (group / domain / anyone) があるとき、`driveMembers_` が
`wide` を立てる。マイドライブは入れ物の `getSharingAccess()` が PRIVATE でないとき。読めなければ unknown。どちらも getEditors や
admins には出ない)。答えは CacheService `ACH_PEOPLE:<小文字のアドレス>` に
覚える (1人・ほかの人がいる は10分、読めなかった `unknown` は2分)。**読めないときは1人と言わない。** 取れる実績が増えても、覚えたクリアはそのまま
(`apiAchievements` の `cleared`。届いたその返事だけ `clearedNow`)。書けるのは管理者だけ (`apiOshiBuiltinProfiles` / `apiOshiBuiltinProfileSet` /
命令 `oshiProfileSet`。どれも `oshiBuiltinProfileSet_` → `repoAssertAdmin_`)。テストの中身は作り話 (「テストの好物」など) にする。
自分のキャラのプロフィールは台帳 (`oshi.profile`) にあり、Drive で台帳を開ける人は直に読める (手引きにそう書いた)。
検査は `oshiProfileValid_` だけ (設定の欄・命令・自分のキャラの欄・置き場から読むとき)。動画のリンクは `focusMusicParse_` で読み解き、
YouTube の動画1本の id だけを残す。

**推しの機嫌 (`src/core/OshiMood.gs`。`apiOshiGet` の `mood` と `apiOshiMood`) は本人にだけ。** どちらもアドレスを受けず、開いている本人の
ぶんだけ数える。ほかの人 (上長・管理者を含む) の機嫌を読む入口は作らない。数えるのは本人のやること (担当に本人。担当なしなら本人が作った
もの = `adviceMadeBy_`。担当は大文字小文字を見ずに比べ、作った人は変更の履歴の字のまま比べる。期限切れも担当の大文字小文字を見ない。改善のヒントの期限切れ (`homeAdvice_`) と「見る」で開く一覧 (`hasAssignee`) も同じく大文字小文字を見ないので、数が揃う)。
やることを消したとき (`issuePurge`) も `issueMoodForget_` で覚えを消す。**変わるのは表情とせりふだけ** で、Lv・実績・ポイント・当たり・プロフィール・クリアは
動かさず、知らせ・メール・使われ方にも出さない。オフ (`oshi.on` か `oshi.mood` が false) の人は台帳を読まない。覚えは CacheService の
`OSHI_MOOD:<小文字のアドレス>` (5分、日が変われば数え直す) と、直ったかを見る `OSHI_MOOD_LAST:<小文字のアドレス>` (6時間) だけで、
台帳とスクリプトプロパティには残さない。やることを済ませた・取り消した・直した・捨てた・戻したときは `issueMoodForget_` (Issue.gs) が
担当の人と押した本人の覚えを消す (待たずに直る)。

**実績 (`src/core/Achievements.js` / `src/core/AchievementsStore.gs` / `src/api/Achievements.gs`) は本人にだけ。**
`apiAchievements` / `apiAchievementsCheck` はアドレスを受けず、開いている本人のぶんだけを数えて返す。ほかの人の実績を読む入口・
順位・チームの合計は作らない (上長・管理者にも返さない)。アドレスを受ける関数は末尾 `_`。**連続日数は持たない** (開いた日は通算)。
まだ取っていない実績は名前・説明・絵を返さない (画面は ???。数のある実績はいちばん近い1つにだけ「あと◯件で…」)。
置き場は台帳ではなくスクリプトプロパティの1つの値: `ACH:<小文字のアドレス>` = `{days: {n, last}, got: {key: 取った日}}` (日は東京の暦日。
値は1つ 9KB までなので時刻を置かない)。前の形 (`ACH_DAYS:` と時刻) は `achRead_` が読んで今の形にし、`achWrite_` (鍵の中) が `ACH_DAYS:` を消す。
**取った印は消さない** (使われ方は180日で間引かれ、完了は取り消せる)。推しの段は、実績の前に届いていた段 (本人の UserProperties の
`OSHI_STAGE_MAX:`) より下にしない (`achStageFloor_`。この鍵は消さない)。その床だけで `crossed` にはしない。床で Lv より上の段に出すときは
`oshiStageOf` が `floored: true` を返し、棒 (`meter`) と `toNext` は出している段の次の段まで Lv1 から数える (画面は「以前のなつき度を保っています」と添える)。
全部を数え直すのは開いたとき (`apiAchievementsCheck()` を引数なしで) だけ。済ませたあとは `apiAchievementsCheck({metrics})` で
変わりうる数えるものだけを数え、頁 (`apiAchievements`) と、その日2回目からの開いたときは、その日に「まだ」と分かった「はじめて」を
CacheService (`ACH_NEG:<アドレス>:<日>`) から読んで数えない (その日の最初に開いたときは全部数える)。手元からの命令の覚え
(`outcomesQueueWindows_`) は1回の数え直しで1回だけ読む。手元からの命令で反映した記録は持ち主の名で残るので、`OUTCOME_QUEUE:` の時間の中なら命令を置いた人のものにする (`achPersonOf_`)。
開いた日は東京の暦日ごとに1回、見ると足すを1つの鍵 (`dbWithLock_`) の中で行う (2つのタブで2日にしない)。取った印も鍵の中で
読み直してから足す (2つのタブで2回「取った」と言わない)。鍵の中で台帳も Drive も読まない。数は台帳と、今あるスクリプトプロパティ
(`STYLE:` / `CAL_PLANNED:` / `MYPREF:` / `OUTCOME_QUEUE:`) と使われ方の場所 (`ACH_USAGE_PLACES()`) から数え、実績のための
記録の表は作らない。止めた人 (`ach.on` オフ) は数えない。

**やることを予定に入れる (`src/api/Calendar.gs`) の入口は、作る・貼る (管理者だけ) を除き開いている本人のぶんだけ。**
アドレスを受けない。カレンダーは本人の権限で読み書きし、**消すのは番頭がその人のために入れた印付きの予定だけ**
(`calendarIsMine_`)。本人の既定のカレンダーは読むだけで、会議の名前を共有カレンダーへ写さない。共有カレンダーの予定の名前は
共有している人に見える (手引きにそう書き、`calendar.title` で「集中」だけにできる)。共有の相手を足す頁の URL は管理者にだけ返す。
細部は `docs/dev/calendar.md`。

**成果の数 (`apiOutcomes`) は管理者だけ** (`repoAssertAdmin_`)。チーム全体の日ごとの数 (`outcomes_daily`) を週ごとに
足して返し、名前もアドレスも入れない。**記録した人が `OUTCOMES_MIN_PEOPLE()` (3) 人に届かない週は数を全部 null にする**
(1人の分が合計からの引き算で見えるため。`gameTeam_` と同じ守り)。週の人数は日ごとの人数の最大で比べる (同じ人を何日も
数えないための下限。本当は3人いた週を隠すことはあっても、2人以下の週を出すことは無い)。終わった週だけを返す
(今週の合計は毎日動き、差から1日ぶんが見える)。画面は設定の画面の管理者の節にだけ出す。
記録した人の数には、手元からの命令で書いた行を持ち主ではなく命令を置いた人として数える (持ち主1人で3人に届かせない。
`docs/dev/ledger-schema.md`)。**時間切れの数 (`error:timeout`) は使われ方の1つの場所で、ほかの場所と同じく押した人と一緒に
`usage` に残る** (`memberVisibleTo` の範囲で人ごとに見える)。成果の数に足すときは人を落として合計だけにする。

**目標 (`src/core/Goal.gs` / `src/api/Goals.gs`) は本人と上長の連なりにだけ見せる。** 既定はオフ (`goals.enabled`)。
見られるのは本人・承認する人・上長の連なり (`goalCanView_`)。**承認する人は直属の上長 (`members.manager`) だけ**で、上長が
登録されていない人は持ち主 (`repoOwners_()`。本人は除く) にする (`goalApprovers_`)。上の上の人は見られるが承認・評価はしない。
**管理者だというだけでは見せない** (人に関わる数を連なりの外に出さない。`memberVisibleTo` と同じ考え方)。持ち主に上長が
いなければ、持ち主は自分の目標の承認を頼めない。アドレスの比べ方は小文字 (`goalLower_`)。`apiGoal*` はどれもアドレスを
受けない (開いている本人として動く)。探す一覧・最近の動き・使われ方・ポイント・メールの本文以外には入れない。
**自動の見立て (`goalAutoScore`) は目安で、評価 (`finalGrade`) は承認する人だけが付ける。** ポイントは使わない。
チームの一覧は名前 → 状態で並べ、進み具合で並べない (順位にしない)。
承認する人に本人は入れない (台帳で自分を上長にしていても持ち主へ倒す。`memberSet` も大文字小文字を見ずに自分を断る)。
**評価は期が終わったか振り返りがあるときだけ** (`goalGradeReady_`。画面の `canGrade` も同じ関数で決める)。
つなげるのは本人のやること (`goalIssueIsOwners_`: 担当に本人、担当なしなら作った人が本人) で、期より前に完了したものは断る。
承認を頼めるかの検査 (`goalAssertSubmittable_`) は、頼むときと承認済みを直して頼み直すときの両方で通す。知らせの関数は末尾 `_`。
状態の移り方は `GOAL_TRANSITIONS()` だけで決める。承認済みの目標そのもの (名前・種類・項目) を本人が直すと `submitted` に
戻す (承認し直し)。今の値・できた印・やることのつなぎは承認し直しが要らない。評価済み (`closed`) は誰も直せない。
台帳 (`goals` / `goal_items` / `goal_links`) は入れ物の中にあり、Drive で台帳を開ける人は直に読める (手引きにもそう書いた)。

**作業雑談部屋 (`src/core/Cowork.gs` / `src/core/CoworkLink.js` / `src/api/Cowork.gs`) は、入った人の名前だけをチームに見せる。**
既定はオフ (`cowork.enabled`)。オフのあいだは部屋もいる人も返さない (`coworkAssertEnabled_`)。見せるのは「入る」を押した人の表示名
(`coworkDisplayName_`。アドレスの大文字小文字は見ない。無ければ「名前未設定」で、アドレスの一部も出さない) と入った時刻・「集中中」(本人が `cowork.showFocus` をオンにしたときだけ) で、**アドレスは返さない**。入口は
アドレスを受けず、開いている本人のぶんだけ付け外しする。**いる印は CacheService にだけ置き、台帳・スクリプトプロパティ・使われ方・
最近の動き・メールには書かない** (誰がいつ入ったかを残さない)。最後の合図から2分で消える。合図は鍵の外で先に読み、名前と「集中中」は入るときと10分ごとにだけ引き直す (合図のたびに人の表を読まない)。**合図では部屋を移らない** (別のタブで別の部屋にいれば `saved: false` と `myRoomId` を返し、画面が合わせる)。キャッシュが読めなければ書かない (空として書き戻すと全員が消える)。1つの部屋の印は 90KB に収める
(キャッシュは1つ 100KB まで。古い合図の人から落とす)。読んで書き直すのは `dbWithLock_` の中で3秒だけ待ち、取れなければ黙って
`saved: false` (次の合図で付く)。部屋を決めるのは管理者だけ (`apiCoworkRoomSettings` / `apiCoworkSetRooms`)。一覧はスクリプト
プロパティ `COWORK_ROOMS` に名前とリンクの部品だけを置く (貼られた字は残さない。Meet の会議・Slack のハドル・Slack のチャンネルだけ)。
**番頭は Meet / Slack の API を呼ばない。** 画面は部品から組み直したリンクを、押した聞き手の中で `window.open(url, '_blank', 'noopener')`
で開くだけ (外から何かを取ってくることもしない)。部屋の中のことは Meet / Slack の決まりに従う (手引き `docs/manual/cowork.md`)。

**最初の画面はホーム (`#panel-home`)。文書タブは文書の一覧だけ。** 文書の上に前進のカードを
並べていたため、どこからが文書の一覧なのか分からなかった。ホームの草は**本人のぶんとチームの
合計だけ** (部下を含めて他人の草を返す入口を作らない)。**連続日数・最長記録は出さない** (途切れた
ときに意欲が下がる)。最近の動きに人の名前を出さない。日報のひな形は `REPORT_TEMPLATES()` が唯一の
定義で、画面の並びは取れなかったときの控え。

**改善のヒント (`homeAdvice_`) の規則・重み・閾値・言葉は `ADVICE_RULES()` が唯一の定義。** 本人のぶんだけ数え
(担当・自分宛て・自分が作った)、報告の規則だけはチームの件数で管理者にだけ出す。名前もアドレスも返さない。
`action.kind` を足すときは画面の `adviceGo` にも足す。「今週は出さない」は端末の `adviceHidden` にだけ覚える。

**横断検索 (`apiSearchIndex`) は題名・番号・状態だけを返す。** 人の名前とアドレスは入れない
(人を探す道は作らない)。画面は欄へ移ったときに1回 (60秒ごと) 取り、手元の `searchFilter` で絞る。
打つたびにサーバへ行かない。返事で画面を切り替えない。
一覧を古いことにするのは `call()` だけで、成功した api の名前で決める (`searchIndexChangedBy`)。
**一覧に出るものを動かす呼び出しは `call()` で書き、名前がそこに当たるかを確かめる。**

## 誰が持ち主かは Session からは分からない

この Web アプリは `executeAs: USER_ACCESSING` で動くため、
**`Session.getEffectiveUser()` は常に開いている本人になる**。持ち主として扱うと
誰もが持ち主になる。`inquiryOwners_()` はリポジトリの入れ物の持ち主を見る。

開いている本人のアドレスは **`currentEmail_()` (`src/core/CurrentUser.gs`) だけで読む** (取れなければ ''。
小文字で比べる所は `currentEmailLower_()`)。`Session.getActiveUser()` を直に書くと `test/sources.test.js` が落ちる。

**共有ドライブには持ち主が無い。** 持ち主は `repoOwners_()` が決め、共有ドライブでは管理者
(`organizer`) 全員になる。`repoOwnerEmail()` を直に呼んで持ち主を決めない。

## 管理者と持ち主は分けて使う

**管理者 = 持ち主 + 入れ物のフォルダを編集できる人** (`repoIsAdmin_` /
`repoAssertAdmin_`)。持ち主1人だけだと、休んだときに誰も設定を直せない。フォルダを
編集できる人は台帳も直接書き換えられるので、画面の操作でも同じ扱いにする。

- 管理者に広げたもの: スクラムの設定、上下関係と他人の表示名、他人の改訂版を捨てる・
  確認依頼を取り下げる・報告を閉じる・下書きを消す
- **持ち主のままのもの**: エディタ専用の関数 (`assertOwner_`)、報告の知らせの宛先と
  報告から作るやることの担当 (`inquiryOwners_`)。宛先を (持ち主でない) 管理者に広げると
  同じ知らせが何通も届く
- **共有ドライブでは** 持ち主 = `organizer` 全員、管理者 = `organizer` / `fileOrganizer` /
  `writer`。グループは数えない。役割は `driveMembers_` が10分覚える。読めないときは誰も
  持ち主・管理者ではない。**共有ドライブの管理者は個人で付ける** (グループだけで付けると持ち主が
  0人になり、`setupCommandQueue` も `debug*` も誰にも動かせない。`docs/manual/setup.md` にも書いてある)
- 報告の知らせは持ち主全員に届く。報告から作るやることは、持ち主が複数なら担当なし
- Drive の `getEditors` は編集権限の無い人が呼ぶと空を返す。分からないときは投げずに
  「管理者ではない」と答える。一覧では1件ごとに問い合わせず、先に1回だけ求める
