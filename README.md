# SoftBanto（そふと番頭） / 通称 番頭

**規程・手順書・名簿のような「間違えられない文書」を、誰がいつ何を直したか残しながら、確認を経て直していくための道具。**
Google ドキュメント・スプレッドシート・スライドに、そのまま使える「版の管理」と「確認の取り次ぎ」を足す。

主に代わって帳面をつけ、段取りをし、確認を取り次ぐ——番頭の役どころから名前を取っている。
リポジトリ名 `agentic-management-gas` は開発上の呼び名としてそのまま残してある。

詳しい使い方は **[使い方の手引き (docs/manual/)](docs/manual/README.md)** にある。画面の中にも、左の「使い方」に図つきの短い説明がある。

## 誰のためのものか

- **総務・人事・法務など、文書を守る仕事の人。** Git やプログラムを知らなくても使える。画面にも、メールにも、
  残る記録にも、エンジニアの言葉 (ブランチ・マージなど) は出さない
- **その文書を一緒に直すチーム。** 直す人・確かめる人・承認する人が同じ画面で話せる
- **Claude Code や Codex を使う人。** 画面を開かずに、手元から文書を直したり、やることを作ったりできる

## 安心して置ける理由

- **Google Workspace の中だけで動く。** 置く人が一度だけ準備し、使う人には開く場所 (リンク) を配るだけ。文書・履歴・台帳は
  すべて自分たちの Google ドライブにあり、ほかのどこにも入らない
- **外のサービスに頼らない。** AI に問い合わせることも、外のサーバに送ることもない (改善のヒントも、決まった規則で番頭が出す)
- **画面に埋め込んで読み込むのは2つだけ。** 集中のしかたの「自分の曲」(YouTube / SoundCloud の公式の再生機) と、
  推しのクリアの「動画を見る」(YouTube の公式の再生機)。どちらも本人が押すまで何も読み込まない
  (作業雑談部屋の「入る」は、Meet / Slack を新しいタブで開きます)
- **手元からの操作も Google ドライブの同期に乗せる。** 合言葉や特別な鍵は要らない
- **正式版は直接なおせない。** 必ずコピー (改訂版) で直し、確認を経て反映する。だから、うっかり上書きされない

## できること

### 文書の版管理

- **正式版と改訂版** — いま効力を持つ正式版は直接なおさず、コピーの改訂版で直す
- **変更の記録** — ある時点の中身を丸ごと残す。誰がいつ何を変えたかが全部残り、いつでも前と見比べられる (左右2列の差分)
- **確認依頼と反映** — 改訂版を正式版に反映してよいか尋ね、承認されたら反映する。複数の文書をまとめて1つの確認依頼にできる
- **食い違いの解き方** — 同じ場所が両方で変わっていたら、どちらを残すかを選んでから反映する
- **Markdown** — 本文を Markdown で読み書きできる
- Docs と Sheets は反映 (書き戻し) まで、Slides は閲覧・履歴・差分まで

手引き: [文書と確認依頼](docs/manual/documents-and-reviews.md)・[考え方](docs/manual/concepts.md)

### やること・ボード・工程表・報告・日報

- **やること** — 誰かがやるべき作業。担当は何人でも、親子・工数・タグ・期限・下書き (ひな形) を付けられる
- **進捗ボード** (これから / 作業中 / 確認中 / 完了)・**工程表** (日・週・月)・**集計** (週〜年度)
- **ホーム** — あなたの番・改善のヒント・草・最近の動き・チームの前進
- **日報にコピー** — 今日片づけたものを、日報の形 (✅今日 / 📅明日 / ⛔️困りごと など) に当てはめて写す
- **要望・不具合** — みんなで読めて返信できる相談板。持ち主のやることに自動で積まれる (持ち主が複数なら担当なし)

手引き: [やること](docs/manual/tasks.md)・[ホームとポイント](docs/manual/home-and-game.md)・[要望・不具合](docs/manual/inquiries.md)

### 人と工数

上下関係・表示名・担当が複数いるときの工数 (頭数で割る)。**人ごとの数は本人と部下のぶんだけ** 見える。
手引き: [人と工数](docs/manual/people-and-effort.md)

### 期間で進める (スクラム。既定オフ)

仕事を作業期間 (スプリント) に区切り、AI のチームメンバー (手元の Claude) と一緒に進める。大きさ・残りの量の推移・
困りごと。言葉は一般の言葉とスクラムの言葉を切り替えられる。手引き: [期間で進める](docs/manual/scrum.md)

### 目標 (既定オフ)

OKR・MBO・KPI を期ごとに立て、上長が承認する。済ませたやることから進み具合と見立てを自動で出す (評価を決めるのは上長)。
手引き: [目標](docs/manual/goals.md)

### 予定に入れる (既定オフ)

担当のやることを、期限の早いものから共有カレンダー「番頭の予定」に並べる。会議と重ねず、番頭が入れた予定しか触らない。
手引き: [予定に入れる](docs/manual/calendar.md)

### 集中 (どれも既定オフ)

- **集中のしかた** — 「今から始める」で長さを選び、最初の一手を1行書く。残り時間の輪・集中の音・技の図鑑 (本人だけ)
- **自分の曲** — 自分の YouTube / SoundCloud の再生リストを、集中しているあいだに公式の再生機で流す
- **作業部屋** — 雨・キーボード・たき火などの環境音を画面の中で作って流し、推しが机で作業している部屋を眺める
- **作業雑談部屋** — チームの Google Meet / Slack の部屋を並べ、いま誰がいるかを見る。番頭は誰が入ったかを記録しない

手引き: [集中のしかた](docs/manual/focus.md)・[作業雑談部屋](docs/manual/cowork.md)

### 楽しさ (どれも本人の画面にだけ出る)

- **楽しい演出** (既定オフ) — 打つと盛り上がる・言葉に反応する・済ませたらお祝い
- **思いがけない当たり・ノリノリタイム・自分へのご褒美** (既定オフ) — 見た目だけの当たりと、自分で決めた小さなご褒美との交換。
  外れも失うものも無く、お金や評価とは関係ない
- **推し** (既定オン) — 済ませたときにキャラクターがほめる。最初からいるキャラか、自分で作ったキャラ (5人まで。AI に作ってもらうこともできる)
- **実績となつき度** (既定オン) — 開いた日 (通算)・済ませた数・はじめて使った機能でバッジが取れ、推しのなつき度 (Lv) が上がる。よそよそしい から 家族 までなつき、自分のことを少しずつ教えてくれる。
  順位も続けた日数も無く、一度取ったものは消えない
- **推しの機嫌** (既定オフ) — やることが滞ると推しがしょんぼりする。変わるのは表情とせりふだけで、何も取り上げない

手引き: [設定](docs/manual/settings.md#思いがけない当たりノリノリタイム自分へのご褒美)・[推し](docs/manual/oshi.md)・[実績](docs/manual/achievements.md)

### 手元の道具 (Claude Code / Codex から)

画面の自分の顔から「手元から動かす道具を落とす」で一式を落とし、Node.js 18 以上と Google Drive for desktop で使う。
命令は Drive に置かれ、1分以内に番頭が実行して結果を返す。

| 命令 | 何をするか |
|---|---|
| `node agent.mjs files` / `read` / `write` / `commit` | 文書の一覧・Markdown で読む・書き換える・変更を記録する |
| `branch` / `pr` / `pr-merge` | 改訂版を作る・確認依頼を出す・反映する (承認は人が画面で行う) |
| `issues` / `issue` / `issue-close` / `board` | やることの一覧・作る・完了にする・ボードの列を動かす |
| `mine` / `advice` / `report` / `search` | あなたの番・改善のヒント・今日の日報の下書き・題名で探す |
| `doctor` | 番頭に頼まずに、設定と入れ先を点検する |
| `oshi-prompt` | 推しのキャラを AI に作ってもらうときの頼み文 |
| `oshi-spinner on/off/status` | Claude Code の考え中の字を、いま使っている推しのせりふにする |
| `track install` / `update` | Claude Code の作業をやることに載せる・道具を新しくする (番頭の署名が合うものだけ) |

手引き: [手元の道具](docs/manual/agent-kit.md)・[コマンドキュー](docs/manual/command-queue.md)

本人はいつでも止められる。手引き: [使われ方](docs/manual/usage.md)

## 言葉の対応

画面とメールと記録に残る文は、右の Git の言葉を使わない。このリポジトリのコードとこの README には
Git の言葉が出てくるので、読み替えに使ってほしい。

| 画面の言葉 | Git でいうと | 意味 |
|---|---|---|
| 正式版 | main | いま効力を持つ版。直接なおせない |
| 改訂版 (改訂中の版) | ブランチ | 正式版をコピーして直している途中の版 |
| 変更の記録 | コミット | ある時点の中身を丸ごと残したもの |
| 確認依頼 | プルリクエスト | ある版を別の版に反映してよいか尋ねるもの |
| 反映 | マージ | 承認された中身を反映先へ書き戻すこと |
| やること | Issue | 誰かがやるべき作業 |
| 進捗ボード | Projects (カンバン) | やることの列 (これから / 作業中 / 確認中 / 完了) |

スクラムまわりの言葉 (作業期間 = スプリント など) は [期間で進める](docs/manual/scrum.md) にある。

## 安全とプライバシー

- **人に関わる数は、本人と部下のぶんだけ。** 工数の内訳・使われ方の人ごとの数は、本人と、上長として登録された人にだけ見える。
  管理者だというだけでは見えない。自分の草は本人だけ (チームの合計は皆に見える)。実績・集中の記録・機嫌・ご褒美は本人にしか見えない
- **ホームの「最近の動き」に人の名前は出さない。** ポイントの順位は、自分で参加を選んだ人だけ (ポイント自体が既定オフ)
- **推しの絵は本人の端末から入れる。** 番頭の画面では本人にだけ見せる。ただし絵は入れ物 (Drive) の中に置くので、
  入れ物を共有している人は直に開ける
- **実在の人の顔は、その人の許しがある場合だけ。** AI に作ってもらうときも、写真やリンクは雰囲気の手がかりにだけ使い、
  実在の人をそのまま描かず、名前や所属を書かないよう頼んでいる
- **外に出るのは、自分で押した埋め込みだけ。** 「自分の曲」(YouTube / SoundCloud) と、クリアの「動画を見る」(YouTube)。
  YouTube は記録を残しにくい埋め込み (youtube-nocookie.com) を使う
- 作業雑談部屋は誰が入ったかを記録しない。会話は Meet / Slack の中で、その決まりに従う

## 制約

- GCP プロジェクトは使えないので `clasp run` (Apps Script API) は使わない。手元からの操作はコマンドキュー経由
- 外部 API・公開エンドポイントは使わない。Drive の拡張サービス (v3) は `appsscript.json` で足してある。
  Google ToDo 連携だけは、エディタで Tasks の拡張サービスを足したときに入口が出る
- 色・フォント・文字サイズは版管理の対象外 (意図的な割り切り)。全角スペースによる字下げも正規化で失われる
- Slides は反映に対応しない (確認依頼を出す時点で断る)
- Drive のネイティブな版の履歴は取れないので、独自の記録 (`.git/objects/`) を持つ
- 手元からの命令は最大1分遅れる (時間主導トリガーの最小間隔)

## はじめに (置く人向け)

最初の一人だけが行う。二人目からは配られた URL を開くだけ。詳しくは [置き方](docs/manual/setup.md)。

```bash
npm ci                                   # テストの依存 (package-lock.json は消さない)
clasp login
clasp create-script --type standalone --title "SoftBanto" --rootDir src
clasp push --force
```

1. GAS エディタで **`setupRepo()`** を一度だけ実行する。スクリプトと同じフォルダに入れ物
   `agentic-management/` (`main/` `branches/` `.git/`) ができ、台帳のスプレッドシートは `.git/` の中に置かれる
2. 手元から動かすなら **`setupCommandQueue()`** も一度だけ実行する (1分ごとのトリガー。1日1回の片付けも載っている)
3. 初回のデプロイを作り、その ID を `deployment.json` に書く。以後は **`npm run deploy -- "何を変えたか"`**
   だけを使う (`clasp create-deployment` を直に叩くと URL が変わる)。先に一度 `node scripts/kit-key.mjs` で
   道具に付ける署名の鍵を作る。**署名の秘密鍵は deploy する人の手元にだけある** (リポジトリにも Drive にも
   番頭にも置かない)。失ったときや、古い版のスクリプトを人と共有する前は `--rotate` で作り直す
   ([管理](docs/manual/admin.md#道具の署名の鍵))
4. 管理したい文書を Drive で `agentic-management/main/` に入れ、画面の **「文書」→「文書を登録する」** で選ぶ

スクリプトプロパティや fileId を人に触らせることはない。

## 開発 (エンジニア向け)

```bash
npx vitest run --testTimeout=60000 --maxWorkers=3   # 全テスト (疑似GAS・jsdom を含む。数分かかる)
npm run test:watch
npm run coverage
npm run deploy -- "何を変えたか"     # kit/ の焼き直し → 署名 → clasp push → 同じ ID へ差し替え
```

- 仕組み: 1つの Google Apps Script を Web アプリとして公開し、その URL を配る。外部 API・公開エンドポイントは使わない。
  手元の道具は Drive 上のコマンドキュー (命令ファイル) で番頭とやりとりするので、API の鍵もトークンも要らない
- ランタイムコードに `import` / `export` / `require` を書かない (GAS で動かなくなる)。テストは
  `test/harness.js` が `node:vm` でソースを評価する
- 配る道具の本体は `kit/`。`src/ui/kit-files.html` は手で直さない
- 守るべき決めごととその理由は **[CLAUDE.md](CLAUDE.md)** と、そこから場所ごとに分けた [docs/dev/](docs/dev/) にまとめてある。構成とテストの詳細は
  [開発の手引き](docs/manual/development.md)

設計の経緯は [これまでとこれから](docs/manual/roadmap.md) と `docs/superpowers/` にある。
