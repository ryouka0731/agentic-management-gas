# 人が読む文の書き方

ここで書く文を読むのは、総務や人事の人です。急いで読んでも取り違えない文にしてください。

## 元に無いことを足さない

- 事実・意見・確からしさを、元の話より強くしない。「次回検討」は「合意」ではありません。
  「たぶん」を「確認済み」にしない
- 日報では進み具合を盛らない。「着手した」を「ほぼ終わった」にしない
- 困りごとを作らない。聞いていない困りごとは書かず、聞いた困りごとは消さない。
  分からなければ書く前に本人に尋ねる
- 聞いていないことと、無いことを分ける。明日の予定や困りごとを聞いていないときは
  「特になし」と書かない。ひな形の節は残して「(未記入。聞いていません)」とし、
  送る前に本人に尋ねる

## 組み立て

- 結論を最初の1文に置く。経緯や理由はそのあとに続ける。日報のように節が分かれて
  いるものは、節ごとに最初の1文をその節の結論にする
- 確認依頼の本文には、何を直したか・なぜ直したか・誰に何をしてほしいか (承認・意見) を
  書く。聞いていないものは作らずに尋ねる
- 読む人が知らないかもしれない言葉は、使う前に一言で説明する
- 原因と結果は、つながった文で書く。「〜のため、〜になった」と書けば読む人が
  因果を補わずに済む。箇条書きの断片に分けると、どれがどれの理由なのかが消える
- 「AではなくB」は、読む人が実際にAと思い込みそうなときだけ使う。言いたいのがBなら、
  Bとだけ書く

## 調子をそろえる

- 1つの文書の中では、です・ます か だ・である のどちらかに決めて通す
- 事実・意見・未確認を書き分ける。たとえば「〜でした (確認済み)」「〜と考えます」
  「〜かもしれません (未確認)」のように、読んだだけで区別がつく形にする
- 太字や絵文字を重ねない。強調は1つの段落に1か所まで。日報のひな形にある節の
  印 (✅ など) はそのまま使ってよい

## この道具の言葉で書く

Git の言葉は人に見せません。`AGENTS.md` の「使う言葉」の表に合わせます。

| 書く言葉 | 使わない言葉 |
|---|---|
| 正式版 | main |
| 改訂版 | ブランチ |
| 変更の記録 | コミット |
| 確認依頼 | プルリクエスト・PR |
| 反映 | マージ |
| やること | Issue |

## 送る前に見直す

段落ごとに次を確かめてから送ってください。

1. 元の話に無い事実・意見・確からしさが混ざっていないか
2. 最初の1文で結論が分かるか
3. 説明していない言葉や Git の言葉が残っていないか
4. 事実・意見・未確認の区別がつくか
5. です・ます と だ・である が混ざっていないか

見直して直せないところがあれば、そのまま送らずに利用者に尋ねてください。
